# L3 Debug 标准工作流

## 调试流程

### 1. 错误信息收集
- 读取完整的编译错误 / 运行时错误信息
- 定位错误发生的文件和行号
- 确认是否是已知问题

### 2. 根因分析
- 从错误信息向源头追溯，不只看表象
- 检查类型不匹配、生命周期、所有权问题
- 检查 API 调用是否正确（验证头文件）

### 3. 修复策略
- 优先最小化修改范围
- 考虑对邻近代码的影响
- 修复后编译验证

### 4. 验证
- 编译通过（`-Werror`）
- 相关测试通过
- 不引入新的警告

## 常见问题排查

| 症状 | 可能原因 | 检查点 |
|------|----------|--------|
| 链接错误 | 缺少源文件 | CMakeLists.txt 是否包含所有 .cpp |
| 头文件找不到 | include 路径未配置 | 顶层 CMake 的 include_directories |
| 模板实例化 OOM | 并行编译过多 | 使用 -j6 限制 |
