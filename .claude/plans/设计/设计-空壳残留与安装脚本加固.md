### 2.2 关键指纹：为什么"全空"是根因的入口

43 个目录**文件数为 0**——即**目录内的文件删掉了，目录本身没删掉**。这个形态排除了多数常见猜测：

| 假设 | 与"全空"是否相符 | 结论 |
|---|---|---|
| 测试中途 abort / 断言提前退出 | ✗（会留下**含文件**的目录） | 降权：boost::ut 的 `expect` 不抛异常，正常路径一定走到清理行 |
| 路径拼错、删了别的目录 | ✗（会留下含文件目录） | 排除 |
| 测试被 Ctrl+C / 超时杀掉 | ✗（同上） | 降权 |
| **清完文件后删目录失败** | ✔ 完全吻合 | **主假设**，见 2.3 |
| CWD 未还原（Windows 下"当前目录删不掉"） | ✔ 形态吻合 | 已取证排除**大部分**：`chdir` 只出现在 `CLFCommandExec.cpp:175` 的 **fork 子进程分支**（`if (child == 0)`），不污染宿主；测试代码里对 `current_path()` 只有**读**，没有 `current_path(dir)` 写 |

### 2.3 主假设：删除挂起（delete-pending）竞态 + 错误码被静默吞掉

MSVC `std::filesystem::remove_all` 的内部顺序是"递归删子项 → `RemoveDirectoryW` 删本目录"。Windows 上文件关闭后可能短暂处于 **delete-pending** 状态（目录项尚未真正消失），此刻 `RemoveDirectoryW` 会失败（`ERROR_DIR_NOT_EMPTY`）。结果是：

```
文件：删掉了（目录看起来是空的）
目录：那一次 RemoveDirectoryW 失败 → 目录残留
```

而当前代码**处处忽略 `error_code`**：

```cpp
~VSetup() { std::error_code ec; std::filesystem::remove_all(dir, ec); }   // ec 从不检查
~TempDir() { std::error_code ec; std::filesystem::remove_all(p, ec); }    // ec 从不检查
```

→ 失败**完全静默**，所以能一路攒到 43 个、跨三周没人发现（9/21 进度文件里记过一次"TEMP 测试残留清理（36 项）"——**那次就是清表没修根，所以这次又是 43 个**）。

同时解释了"为什么只有部分运行残留"：竞态是概率性的，跑 10 次可能留 2–3 个，正好对得上"每个用例 3 份残留"这种零散分布。

### 3.2 `install.ps1` 逐点取证

| 位置 | 现状 | 风险 |
|---|---|---|
| `:6` | `$ErrorActionPreference = "Stop"` | 决定了撞锁**立即中止**（而非继续）——所以留下"半删残骸" |
| `:81-95` | 备份用户数据 → `:94 Remove-Item $INSTALL_DIR -Recurse -Force` | **无任何"是否在运行 / 是否被占用"前置探测**；删除失败即半删 |
| `:104-109` | `Move-Item -Path $innerDir.FullName -Destination $INSTALL_DIR -Force` | **目标已存在时 PowerShell 会把新版本塞进旧目录**（`CLFCode\CLFCode-v0.8.1\`）。当前被 `:6` 的中止"意外掩盖"，属**潜伏缺陷** |
| `:124` | `Remove-Item $backupRoot -Recurse -Force` | 清理**只在成功路径**执行 → 中止时备份永留 TEMP（今天 2 份 + 8/25–8/31 的 8 份空壳，全是中止留下的） |
| `:166-181` | `Test-Path "$binDir\CLFCode.exe"` 验证 | 有验证 ✅（但残骸已经产生，验证只是告知） |

> **修正一个此前的错误猜测**：备份残留**不是**"脚本忘了清备份"，而是"中止在清理之前"——同一个根因（撞锁中止）的两个表现。

### 3.3 `upgrade.ps1` 逐点取证（**比 install 更危险**）

| 位置 | 现状 | 风险 |
|---|---|---|
| `:6` | `$ErrorActionPreference = "Stop"` | 同上 |
| `:85` | `Remove-Item -Path $INSTALL_DIR -Recurse -Force **-ErrorAction SilentlyContinue**` | **静默失败后继续往下走** |
| `:94` / `:96` | `Move-Item … -Destination $INSTALL_DIR -Force` | 承接上一条：目录没删干净 → **嵌套安装** `CLFCode\CLFCode-v0.8.1\…` |
| `:116` | PATH 写入 `$INSTALL_DIR\bin\Release` | 嵌套后该路径**不存在** → 用户敲 `CLFCode` 找不到命令，且新旧文件混在一棵目录里 |

**结论**：同一故障（安装目录里有文件被占用）在两个脚本里走向两种坏结局——
- `install.ps1`：**中止** → 半删残骸（本次实际发生）
- `upgrade.ps1`：**静默继续** → 嵌套安装 + PATH 失效（未被触发，但风险更高）

用户本次用的是 install.ps1 才只吃到"残骸"，若按脚本提示改用 upgrade.ps1，后果更重。

### 3.4 加固设计（待裁决）

| 编号 | 措施 | 落点 |
|---|---|---|
| S1 | **前置占用探测**：删目录前检查 `$INSTALL_DIR` 内是否有关键文件被占用（Restart Manager API 或"对关键文件尝试独占打开/改名"）；命中则打印**占用者 + 文件路径**并 `exit 1`，提示"请先退出 CLFCode 再安装" | 两脚本共用同一段（抽出函数） |
| S2 | **改"删"为"改名后删"**：`Move $INSTALL_DIR → $INSTALL_DIR.old-<guid>`（同卷改名，对在用目录也能成功）→ 装新 → 最后尽力删旧名；删不掉就提示用户手动清。收益：① 绝不半删在用目录 ② **天然规避 S3 的嵌套**（新目标名必然不存在） | 两脚本共用 |
| S3 | **`Move-Item` 防御**：Move 前断言目标不存在（存在即报错退出），不再依赖"上一步删干净了" | 两脚本 |

## 四、附：环境因素（**不是 CLFCode 缺陷，但会再次触发上面的问题**）

今天锁文件的不是 CLFCode，而是**agent 会话遗留的孤儿进程**（10 findstr + 4 cmd，父进程全死，卡在断掉的管道上数小时）。这类孤儿会**随机吊住任意文件句柄**——只要它扫过那个目录，安装/升级脚本就会撞锁。

**巡检命令**（怀疑"文件被莫名占用"时先跑这个）：

```powershell
Get-CimInstance Win32_Process | Where-Object { $_.Name -in 'findstr.exe','cmd.exe' } | ForEach-Object {
  $p = $_; if (-not (Get-CimInstance Win32_Process -Filter "ProcessId=$($p.ParentProcessId)" -EA SilentlyContinue)) {
    "孤儿: PID $($p.ProcessId) $($p.Name) start=$($p.CreationDate) cmd=$($p.CommandLine)" } }
```

**定位"谁锁着某文件"**（Restart Manager，无需 handle.exe）：

```powershell
# 见本次会话所用的 Add-Type 片段（rstrtmgr.dll: RmStartSession/RmRegisterResources/RmGetList）
```

加固后 S1 可把这套探测**内置进脚本**，用户不必自己排查。
