# 归档-测试策略

> 状态：✅ 已实现，6 个测试全部通过 | 提交：05174de + 后续修复

## 设计目标

按三层策略落地 L1 单元测试 + L2 Mock 集成测试。核心原则：**不测试 LLM，测试代码对 LLM 响应的处理能力。**

## 设计决策

| 决策 | 结论 |
|------|------|
| 测试框架 | Boost.UT（`3rdparty/boost-ut/`，unittest.md skill 约定） |
| 语言标准 | 测试目标 C++20（Boost.UT 要求），主程序保持 C++17 |
| 测试目录 | `src/test/qa_*.cpp` |
| Mock 机制 | `ICLFHttpClient` 抽象接口（DIP 重构），`MockHttpClient` 按序消费预设响应 |
| main 处理 | Boost.UT 测试静态注册 + `cfg` 析构自动运行，测试文件需 `int main()` |

## 测试清单

### L1 单元测试（4 个）

| 测试 | 覆盖 |
|------|------|
| `qa_CLFContext` | token 估算（ASCII/CJK）、system 永不截断、长结果截断、serialize/restore round-trip、无效 JSON |
| `qa_CLFProtocolAdapter` | 4 角色序列化、tools 构建 + tool_choice、响应解析、畸形 JSON 防御、非法 Schema 降级 |
| `qa_CLFSecurityPolicy` | 4 模式 × 3 风险行为矩阵、modeFromString、getModeName、动态切换 |
| `qa_CLFSessionManager` | save/load round-trip、incomplete 命名/查找/promote、list 排序、cleanupOld |

### L2 集成测试（1 个）

| 测试 | 覆盖 |
|------|------|
| `qa_CLFAgentLoop` | Mock HTTP：tool-calling 循环（先 tool_calls 后 stop）、Analyze 模式阻断（handler 不执行）、流式 SSE 累积 |

## 测试过程中发现并修复的 bug

| Bug | 修复 |
|-----|------|
| Boost.UT 不生成 main → 链接失败 `无法解析的外部符号 main` | 每个测试文件末尾补 `int main() { return 0; }` |
| 测试目标漏链 OpenSSL → `BIO_*`/`ERR_*` 未解析 | qa_CLFAgentLoop 链接 `${CLF_OPENSSL_LIBS}` |
| **同秒会话保存互相覆盖**（真实数据丢失风险） | `CLFSessionManager::save()` 文件名冲突追加 `-2`/`-3` 序号 |

## 构建与运行

