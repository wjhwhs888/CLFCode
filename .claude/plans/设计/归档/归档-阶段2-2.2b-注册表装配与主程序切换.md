## 二、read_file 校验归属定案（2.2a §二 硬约束的兑现）

**2.2a 倾向"校验移宿主侧"——取证后修正为更顺的方案：保持 handler 层校验（S2-1 原定案），插件经 host->config 取根。**

| 方案 | 评估 |
|---|---|
| ~~校验移宿主侧装配处~~ | 装配 = 通用元数据映射，混入安全逻辑破坏简洁；且 read_file 特有分支散入宿主 |
| ✅ **插件经 config 取根，handler 层校验保持** | ABI 已有 config 通道（零 ABI 变更）；CLFHostApiImpl::config 接真实现时支持**宿主级键**（与插件配置文件的键同通道）；校验逻辑留在共享 handler（单点） |

**实现链**：
1. `CLFConfigLoader` 加静态缓存 `s_allowAbsoluteRead`（loadFromFileWithEnv 时赋值，getWorkingDir 同款）
2. `CLFHostApiImpl::config(pluginId, key)` 接真实现：
   - **宿主级键**（任何 pluginId 都适用）：`"workspace_root"` → getWorkingDir()；`"allow_absolute_read"` → s_allowAbsoluteRead 的 "true"/"false"
   - **插件键**：读 `config/plugins/<pluginId>.json`（懒加载缓存）；key 未命中/文件缺失 → nullptr
   - 按 key 缓存进 m_configCache（§3.4 设计）
3. `CLFFileOpsPlugin::init()` 读 `host->config(..., "workspace_root")` / `"allow_absolute_read"` 存成员（缺失 → 空串/false 兜底）；`callTool` 的 read_file 路由传该值——**校验语义与静态路径完全一致**

## 三、registerPluginTools 装配（元数据 → CLFTool）

```cpp
// CLFBuiltinTools.hpp/.cpp（clf_tools 层，与 registerBuiltinTools 同层）
// 从插件管理器收集 tool.provider 提供者的全部工具，装配注册。
// handler 捕获 manager 引用、**调用时经 getService 查询**（不缓存服务指针——
// §1.2 禁跨 unload 缓存；卸载后查询 nullptr → 走兜底错误文本，验证点 4 的自然实现）
void registerPluginTools(CLF::CLFCore::CLFAgentLoop& agent,
                         CLF::CLFCore::CLFPluginManager& manager);
```

**装配规则**：
- 遍历 `manager.toolProviders()` → 每个 provider 的 `toolMeta(i)` → CLFToolMetaPOD → CLFTool：
  - m_name/m_description/m_parametersSchema 直接复制
  - m_risk = static_cast<CLFToolRisk>(risk)（枚举序 0-2 与 CLFToolMetaPOD 约定一致）
  - m_isRead = flags & ToolFlagRead；m_isSearch = flags & ToolFlagSearch（B1 标签跨边界映射）
  - m_concludesTurn = concludesTurn != 0
  - m_handler = `[&manager, name](args) { auto* svc = manager.getService("tool.provider"); if (!svc) return 兜底错误JSON; return static_cast<ICLFToolProvider*>(svc)->callTool(name, args, ctx收集); }`——回调收集结果文本（onResult/onError 同收）
- **工具名查重**：与已注册（core 2 工具）冲突 → 跳过 + warn（防御，当前无冲突）
- 兜底错误文案：`{"success":false,"error":"工具提供者不可用（插件已停用）: <name>"}`——与既有失败路径同构（formatToolResult 判定 error）

**CLFBuiltinTools.cpp 变化**：删 read/write/edit/list 4 个注册段（共享 handler 保留——插件消费者；`registerBuiltinTools` 缩为 5 工具 + 2 core）。

## 五、main 装配链（main.cpp 变化）

```cpp
// 现状（main.cpp:145-146）：
//   CLFAgentLoop agent(config);
//   registerBuiltinTools(agent);
// 目标：
CLF::CLFCore::CLFPluginManager pluginManager;      // 缺省 exe 目录/plugins
const int pluginCount = pluginManager.loadAll();   // 无插件 → 0，静默降级
CLF::CLFCapabilities::CLFFileServiceProxy fileProxy(&pluginManager);
CLF::CLFCore::CLFAgentLoop agent(config, &fileProxy);
CLF::CLFTools::registerBuiltinTools(agent);        // 5 工具 + 2 core
CLF::CLFTools::registerPluginTools(agent, pluginManager);   // 插件工具装配
```

**降级语义（如实声明）**：插件目录缺失/插件加载失败 → fileops 4 工具**不注册**（模型不可见、不可调）——不做静态 fallback 双注册（双路径维护成本 + 卸载语义混乱；§3.6 兜底链："停用后模型再调 → 明确错误"依赖工具**已在注册表**+ 调用时查询——已停用场景由 handler 兜底文本覆盖）。核心功能（对话 + 其余工具）不受影响。
