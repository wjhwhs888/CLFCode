## 三、排期方案（四波 + 一个观察任务）

### 第一波：中断根因闭环（P0，用户痛点）
**范围**：中断时效性 A 批全部 10 步 + A2 三慢点接入 + B 批紧急子集（B2 双击退出 (a)+(b)、W6 状态行单写、B4 去 clear）+ C 批子集（批C-1 世代号最小版、批C-3 注释、批C-4 测试）+ repair-on-load + 命令执行层步骤 0-3/6
- ABI：`CLFToolCallbacks` 尾部追加 `isCancelled` + 头注释改写 + `CLF_PLUGIN_API_VERSION` 1→2
- 宿主接线：`CLFAgentLoop::interruptFlag()` 访问器 + `CLFPluginTools` ctx 化（CLFToolCallCtx{out, interrupt}）
- 命令执行器：CLFProcessRunner 落地（等价搬移→取消检查→Job Object 杀树+超时同改→POSIX 分支 setsid/kill(-pgid) 标 [未验证]）+ 超时默认 120s/上限配置项 600
- handler/插件壳下传取消查询；协议闭合（AgentLoop :366 前差集补配对，两段定稿文案）；日志
- A2：web_fetch（httplib stop 接入）/ search_content（循环检查点）/ 摘要入口
- 测试：qa_CLFProcessRunner C1-C5（含 C3 心跳文件杀树探针）+ 声明数==结果数 + I1/I2/I3 不变量 + teststub isCancelled 断言
- **验收门**：ctest 全绿；实机 node test_ai.js 中途 ESC ≤1 秒停 + 无 node 残留 + 中断后继续对话不 400 + 状态不被刷 + 模型看到"结果未知"不盲目重试

### 第二波：命令执行层收尾（G2/G3）
- 步骤 1：执行器层 256KB 限额 + 命令 tool result 头尾 8KB×2 口径（复用 headTailCapBytes/headTailCapWithMarker，不写第三份）
- 步骤 4：错误归一化 m_errorKind 六枚举 + JSON errorKind 字段（原始 stderr 保留）
- 步骤 5：CLFSubprocessRunner argv 门面 + 消 2>nul（含 `ver` 待核实项定案）
- 测试：C4/C6/C7/C8/C9；验收：长输出命令模型能看到尾部结论

### 第三波：平台层收敛（零行为变更基建）
- 步骤 0-7：CLFPlatform 骨架 → executableDir 合一 → 动态库后缀 → 控制台原语（风险最高放最后）→ 剪贴板 → 2>nul 修复 → 临时文件口径（删 CWD 清理死代码）→ qa_CLFPlatform
- 验收：ctest 37/37 + --version 逐字节 + 非测试 #ifdef 35→≤10 + 用户实机抽验（拖选/复制/中文输入/四域插件）

### 第四波：P1 收尾
- 中断 B 批剩余：B3 Ctrl+C 收尾统一、W-usage、quiesce 回归用例
- 批C-2（W4 等首字节）维持砍除，除非实机暴露

### 观察任务（不入队列）
- 窄窗口渲染异常：登记 progress 长期观察区，跨平台验证时按文档 §四.2 观察清单取证

### 关键耦合与顺序约束
1. 中断 A 批 ≡ 命令执行层 G1（同一实现），必须同波
2. **交叉冲突 A（排期二轮审查新增）**：命令层步骤 5（argv 化消 `2>nul`）与平台层步骤 5（`nullDevice()` 收敛）动**同一批代码点**（`CLFSystemInfoProvider.cpp:82/90/100`）——第二波 argv 化先行 → 第三波平台层步骤 5 整改对象消失，缩减为"随 `ver` 定案销号"；若 `ver` 走 CLFPlatform 版本原语，`nullDevice()` 接口可整体裁剪
3. **交叉冲突 B（二轮审查新增）**：CLFCommandExec.cpp POSIX 补 `<signal.h>` 被中断 A.3 步骤 4 与平台层 E 类清单双列——第一波顺手补，平台层 E 类销号
4. **波间依赖**：CLFProcessRunner 第一期落地**不依赖 CLFPlatform**（Windows 实现直用 Win32），避免第一波依赖第三波；落点（CLFTypes 或 CLFTools）实施时按插件 CMake 链接结构定
5. **实现方式细化（更小解，二轮审查）**：
   - W6 状态行单写倾向"中断中 = 不可覆盖的高优先级状态"，**不新增 ICLFOutput 接口**（避免 CLFTerminal + 全部 mock 连锁改动）
   - repair-on-load 倾向**内存闭合**（loadJsonl 载入时补进内存），jsonl 持久化可选——便宜且满足"恢复后不 400"
   - 协议闭合"未执行"结果在 **CLFToolExecutor 内产出**（中断 break 后为剩余 calls 补合成结果，`results.size() == toolCalls.size()` 恒成立），AgentLoop 零差集逻辑
6. 每波内按步骤小步提交（每步独立可验、独立可回滚）
7. 用户拍板项全部保留：D1 立即强杀 / D2 协议闭合反馈 / D3 全域可中断 / D5 用量计入 / D6 半截不入库 / D7 选区 ESC / D8 待办面板 / D10 术语 / 超时 120s+600 配置
