## 二、重构方案（按批次）

### 批次 A：纯搬移 / 抽取（低风险，不动行为，可先行验证）

**A1. CLFRepl 拆分（P0-1）**
```
CLFRepl.cpp (1006行) → 
  CLFRepl.cpp      （瘦壳：run 编排 + 组件装配）
  CLFReplView.cpp  （新：Renderer 逻辑——行映射/wrap/高亮/spinner/状态点/状态栏/todo面板/Tips 渲染）
  CLFInputHandler.cpp（新：CatchEvent 逻辑——按键分发表 + 提交/粘贴/确认/选区/历史/Esc）
  纯搬移，不改行为；顺带把 183-203/822-845 ANSI 剥离抽 stripCprResidual()
```

**A2. 公共字符工具（P0-3/P1-8~11）** → 集中到 `CLFEncoding`（已有 isValidUtf8）或新 `CLFTextUtil`
```
utf8SafeHead(text, maxBytes, ellipsis)   ← 替换 ≥6 份安全截断 + ≥6 处不安全截断
displayWidth(str) / charWidth(c)          ← 统一 SelectionModel + Terminal 两套
splitLinesKeepEmpty(text)                 ← 替换 ≥3 处换行拆分
localNow(fmt)                             ← 替换 ≥6 处时间戳+平台 ifdef
stripCprResidual(std::string&)            ← 替换 ANSI 剥离 2 处
```

**A3. SessionManager 死代码清理（P1-6）**
```
删/归档：legacy save（193-274）、findIncomplete/removeAllIncomplete/promote（572-619）
保留：load 兼容旧 .json（恢复旧会话用）；list 标题提取改复用 loadJsonl 逻辑
```

**A4. handler 脚手架（P1-5）**
```
CLFBuiltinTools 抽：okResult(json)/errResult(msg) + 统一 parseJson 包装
8 个 handler 的 try/catch/success=false 收敛
```

### 批次 B：防雪崩接口化（功能扩展前必做，需谨慎设计）

**B1. CLFTool 能力标签（P0-2）**
```cpp
// CLFTool 加能力标签（照 m_concludesTurn 先例）
struct CLFTool {
    ...
    bool m_concludesTurn = false;   // 已有
    // 新增能力标签
    bool m_writesFile = false;       // 替代 executor 里 == "write_file"/"edit_file"
    bool m_runsCommand = false;      // 替代 == "execute_command"
    bool m_hasRemoteSideEffect = false; // 替代 == "web_fetch" POST 升级
    bool m_isSearch = false;         // 替代 name.find("search") 统计
    bool m_isRead = false;           // 替代 name.find("read")
};
// CLFToolExecutor 删除全部名字匹配，读标签
```

**B2. 会话生命周期收敛 core（P0-4）**
```cpp
// CLFAgentLoop（或新 CLFSessionCoordinator）提供用例级方法：
  startNewSessionFile(firstInput)   // 现在在 CLFRepl::submit
  endSessionAndSummarize()          // 现在在 cmdClear
  resumeTo(path)                    // 现在在 cmdResume
  appendTurnAndClose()              // 现在在 submit/exit
// CLFCommands 变薄壳：只调方法 + 回显
```

**B3. UI 概念移出 core（P0-5）**
```

      或 UI 层自行从 todos 推导面板显示（面板隐藏= 全完成 或 用户已收）
```

**B4. 恢复回显外移（P0-6）**
```
restoreSession 不再拼 📋/✓ 文案
→ SessionManager 返回结构化行（type+数据），UI 层负责渲染折叠块
```

**B5. ICLFOutput 纪律（P1-2，低风险先行）**
```
规则固化：新方法一律带默认实现（已自发采用，注释写明）

（拆窄接口放 P2，涉及 5 类改动大）

### 批次 C：结构性重构（需设计评审，影响大）

**C1. CLFFileOps/CLFDiff 归属修正（P1-12）**
```
二选一：
  a) 文件移入 CLFCore 目录（诚实归属——它们是 core 文件原语）
  b) 定义能力层（FileOps/Diff/CommandExec/Search/WebFetch 整体为 core 下的被依赖层）

## 三、改造原则（全程遵守）

1. **纯搬移先行**（批次 A 不改行为）——每步验证 ctest + 人工冒烟，防雪崩
2. **功能扩展前完成批次 B**（防雪崩接口化）——否则加功能仍会踩名字匹配/UI 编排
3. **批次 C 需设计评审**——涉及接口拆分的调用面，需 pro 评估成本
4. **每批次独立可交付**——不追求一次重构完，逐步推进
5. **不新建同级目录除非必要**——当前用"文件内拆分 + 抽取"解决；会话模块化等 A/B 落地后看实际需要
