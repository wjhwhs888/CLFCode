## 定稿摘要（pro 先读这一页）

**一句话**：把"人工按提示词跑一遍 + 肉眼看 ✗"升级为**用例文件驱动的可判定回归**——`--prompt` 逐例拉起非交互会话，从 **jsonl + 日志 + stdout + 工作区 diff** 提取事实，按**断言原语**判定 PASS/FAIL，出报告。

**三层分工（关键：别把能确定的交给 LLM 判）**：

| 层 | 覆盖 | 成本 | 谁判 |
|----|------|------|------|
| ① `ctest`（Boost.UT，已有 39 套件） | 执行器/白名单/错误归一化/**显示规则** | 免费、确定 | 断言 |
| ② **本方案 AT（Agent Test）** | **真 LLM + 真工具链的行为与信号** | 花钱、非确定 | 断言 + 少量判官 |
| ③ 人工验收清单 | **交互类**（ESC 中断、确认栏、拖选、Home/End） | 人工 | 人 |

**核心原则**：**负向断言优先**（"不得出现 `head`"稳、"必须说出 X"不稳）；**成本也是断言**（token/时长/工具调用次数上限——正好把"无界轮询"变成可判定）；**必须有负控**（故意注入已知缺陷，harness 必须报 FAIL，否则"全绿"无意义）。

**实现归属（重要）**：**驱动用什么语言、目录怎么摆、用例文件什么格式、断言库怎么设计、报告长什么样、CLI/环境变量怎么命名——全部由 pro 定。** 本文只规定三件事：**要能观测什么**（§5.2）、**要能判定什么**（§五/§六）、**受什么约束**（§七/§九）。

**前置缺口（步骤 0，必须补）**：现有 CLI **没有** session/log/history 目录参数（`CLFArgParser.cpp:12-57` 只有 `--config/--project-root/--prompt/--prompt-file/--allow-write`）→ 用例会污染真实 `doc/contextHistory` 与 `doc/log`，**须具备按例隔离落点的能力**（项目已有 `CLFCODE_TEST_*` 环境变量先例可沿用；**具体命名与实现由 pro 定**）。

## 一、目标与非目标

**目标**：
1. 把人工提示词测试固化为**可重复、可判定、可回归**的用例集；
2. 每个用例输出 **PASS / FAIL / UNKNOWN** 三态（**UNKNOWN 不许当 PASS**）；
3. 让"模型行为退化"能被**自动发现**（例如某次改动让模型又开始用 `head`）；
4. 把**成本**纳入判定（token/时长/工具调用次数）。

**非目标**：
- 不进 `ctest` 常规套件（要联网、花钱、非确定）——独立入口，手动/夜间触发；
- 不替代 ctest 单元测试（能确定的逻辑一律下沉到 ctest）；
- 不做"模型输出质量打分"的通用评测（只做**项目关心的行为回归**）。

## 三、与现有测试体系的关系（三层，别混）

```
① ctest（进程内、确定、免费）       ② AT（真 LLM、非确定、花钱）        ③ 人工（交互）
   执行器 / 白名单 / 归一化      ←→    模型行为 + 端到端信号         ←→   ESC / 确认栏 / 拖选
   ↑ 能下沉的一律下沉                        ↑ 本方案                        ↑ 结构化清单
```

**分工判据**：凡是"给定输入 → 确定输出"的逻辑（含 `formatToolResult` 的显示规则），**一律用 ctest 覆盖**；只有"依赖模型决策"的部分才进 AT。
> ⚠ 实例：X13（显示 ✗ 只看 `exitCode`、忽略 `success`）**属 ctest 可覆盖**——不该等 AT 才发现。

## 四、运行形态（**实现由 pro 定**）与单例流程（方案级约束）

> **边界声明**：harness 的**驱动语言、目录结构、用例文件格式、断言库设计、报告格式、CLI/环境变量命名与接线——全部由 pro 决定**。本文只规定：**要能观测什么**（§5.2）、**要能判定什么**（§五/§六）、**受什么约束**（§七/§九）。下面只写"行为要求"，不写实现形态。

**单例流程（必须满足的行为约束）**：

1. 每例使用**独立工作区** + 独立配置 + **隔离的会话/日志/历史落点**（§七）——不得污染真实 `doc/**`；
2. 以**非交互**方式发起该例提示词（现有 `--prompt` / `--prompt-file` 通路已具备）；
3. 采集 §5.2 所列事实源；
4. 按用例声明的判定项得出 **PASS / FAIL / UNKNOWN**（三态，UNKNOWN ≠ PASS）；
5. **重复 N 次**（默认 3），全过才算 PASS，并记录通过率；
6. 触到成本门 → **立即中止该例并判 FAIL**（不许挂死）；
7. 结束清理临时目录，工作区必须干净（`git status --porcelain` 无新增）。

## 五、判定三层 + 断言原语

### 5.1 判定分层

| 层 | 手段 | 适用 | 强度 |
|----|------|------|------|
| **确定性** | 从 jsonl/log 提取事实做断言 | 工具序列、命令文本、重复、悬空、退出码、**成本** | **最强（首选）** |
| **半确定性** | stdout/文本关键词 | "含 `cmd.exe`"、"不含 `此时不应有 &`" | 中 |
| **LLM 判官** | 独立模型 + rubric 打分 | "解释得对不对""是否误导用户" | 弱（**不可判必须记 UNKNOWN，禁止猜**） |

### 5.2 断言原语（从采集事实派生，供用例引用）

| 原语 | 事实来源 | 说明 |
|------|----------|------|
| `toolCallsMax` / `toolSeq` | jsonl | 工具调用次数与顺序 |
| `cmdMustNotMatch` / `cmdMustMatch` | jsonl（`execute_command.command`） | 命令文本正则（**负向优先**：`\| head`、`findstr .* -A`、`start /b`、`%ERRORLEVEL%`） |
| `noRepeat` | jsonl | 同一条命令**连续重复次数 ≤ 1** |
| `noUnpairedCalls` | jsonl | 声明数 == 结果数（协议闭合，恒真不变量） |
| `displayStateNot` | stdout / ctest 侧 | 用户可见状态不得为某值（如 ✗）——**显示规则优先下沉 ctest** |
| `errorKindIn` / `errorKindNotIn` | jsonl | 归一化错误类 |
| `budget.tokensMax` | 会话统计 | **成本门** |
| `budget.wallClockSecMax` | 计时 | **成本门** |
| `workspaceClean` | `git status --porcelain` | 无临时文件残留 |
| `exitCodeIn` | 进程 | 非交互模式退出码 |
| `judge` | LLM | 语义类（可选） |

### 5.3 非确定性的处理纪律

1. **负向断言优先**：把"应该做对"尽量改写成"不该做错"；
2. **repeat N**（默认 3）：全过才算过，报告记通过率；
3. **固定变量**：同 `--config`、同模型、同 prompt、同 fixture；
4. **UNKNOWN ≠ PASS**：判官无法判定或数据缺失 → UNKNOWN，且必须进报告。

## 七、隔离与成本门（本方案的安全阀）

**隔离（步骤 0 的前置）**：建议新增 CLI 参数或环境变量（**沿用既有约定**）：
- `--session-dir <path>` / `--log-dir <path>`（或 `CLFCODE_TEST_SESSION_DIR` / `CLFCODE_TEST_LOG_DIR`）
- 目标：每例独立目录，**不写真实 `doc/contextHistory`、`doc/log`、`doc/debug`**；
- 每例结束**必须**清理临时目录（harness 侧 RAII 等价物）。

**成本门（硬性）**：
| 门 | 默认 | 超限行为 |
|----|------|----------|
| 单例 wall-clock | 180s | **杀进程 + FAIL（记 `timeout`）** |
| 单例 token | 60k | **杀进程 + FAIL（记 `over-budget`）** |
| 单例工具调用数 | 用例声明 | FAIL |
| 整套运行 | 15 min | 停止并出报告 |

> 意义：把"模型无限轮询"从"用户手动 ESC"变成**自动失败**——这正是人工轮暴露的第一号成本问题。

## 十、已知边界

- **交互类无法纯自动**（ESC/确认栏/拖选/Home-End）→ 保留人工，但**结构化**：固定清单 + 每步记录（沿用 2026-09-23 的 todo 记录法，升级为 `测试-人工验收清单-*.md`）；
- **半自动中断测试**成本高（需 pty/`CTRL_BREAK_EVENT` 注入）→ 列为后续增强，不阻塞 MVP；
- **LLM 非确定性**：正向语义断言天然不稳 → 靠负向断言 + repeat + 判官兜；
- **钱与网络**：默认小用例集、手动触发；**不得**进 CI 默认流水线（除非有额度预算）。

## 附 B：假设与反证

| 假设 | 强度 | 若为假 | 反证方法 |
|------|------|--------|----------|
| 非交互模式足以覆盖大部分行为用例 | **中强** | 若 `--prompt` 路径与交互路径**行为不一致**（如工具确认/中断逻辑不同）→ 断言结论不可迁移 | 同一用例分别用两种模式跑，比对 jsonl 工具序列 |
| 断言可从 jsonl 稳定提取 | **中强** | 若 jsonl 字段随版本变动 → 断言脆 | 先固定字段契约（写进 §5.2），并在用例里校验字段存在，缺失记 UNKNOWN |

| 每例 3 次重复成本可接受 | **中** | 若太贵 → 降到 1 次，仅关键例 3 次 | 统计实际 token |
