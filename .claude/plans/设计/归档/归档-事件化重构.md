## 二、现状与总目标

**现状**（v0.9.1+，分析文档 §二取证）：
- 依赖方向正确（core 零 include CLFTUI、ICLFOutput 接口倒置），但**合同是 TUI 形状**：
  - core 拼 UI 文案（✻ Worked / 📋 清单收尾 / ⏹ 已中断 / "Working for" 状态行）且混入 jsonl 落库
  - confirm 阻塞式回调、覆盖式单行状态槽、样式枚举、折叠块——进程内单 TUI 假设的产物
  - AgentLoop::runTurn 单函数约 440 行（God Function），工具执行严格串行

**总目标**：core 与 UI 之间改为**事件总线唯一通道**——core 发语义事件、各 UI（TUI/Qt/HTML）订阅渲染、数据与显示分离、协议头文件即规范。分两阶段推进：**第一批"摘干净显示"（步骤 0-3，TUI 零破坏）→ 第二批"并发执行"（步骤 4）→ 第三批"跨进程与新 UI"（步骤 5，占位）**。

**两个世界（沿用插件化总纲术语，机制不同）**：

| | 本地 UI 世界（第一批） | 跨进程 UI 世界（第三批） |
|---|---|---|
| 内容 | CLFTUI（现有终端界面） | Qt / HTML 等新 UI |
| 机制 | 进程内事件总线（订阅队列） | 事件序列化 + 传输层（JSON/WS） |
| 协议 | CLFEvents 头（进程内直接调用） | 同一事件模型序列化（协议规范 = 同一头文件） |

## 四、各步骤主要工作与排期要点

### 步骤 0-2（分册 1：AgentLoop 拆分与事件总线——第一批核心）
1. runTurn 拆 5 个 Section 函数（prepareTurn / requestAssistantTurn / executeToolCalls / finishTurn / runWrapUp），lambda 提成员函数，纯搬移零行为变化 → ctest + 实机回归
2. CLFEvents 协议头（CLFTypes 层，零依赖）：语义帧 + 增量旁路双通道、confirm 请求-响应原语（requestId + 超时默认拒绝）、turnId/callId/seq 稳定关联键
3. CLFEventBus：每订阅者队列（有界 + 溢出策略：语义帧保序不丢、增量可合并丢弃）、单生产者保序、订阅者线程消费（慢消费者不阻塞内核）、无人订阅缓冲不丢弃
4. 发射点挂接 + CLFTerminalEventAdapter（事件→ICLFOutput 映射，TUI 观感逐字对齐）
> 排期：步骤 0 先行（独立可验收）→ 步骤 1-2 一体实施；每步 ctest + 冒烟；步骤 2 验收 = 输出快照对比

### 步骤 3（分册 2：文案迁移与会话落库恢复）
1. 装饰文案迁移：turn_finished{workedSec,todoSnapshot} 由适配器拼 ✻/📋 行 emit；⏹/kTurnCapNotice 同路径；状态行文案归 UI（core 只发 status_changed）
2. jsonl 新数据模型：turn 行纯消息（无装饰）+ 稳定 id（turnId/callId）；装饰行由 UI 在 resume 回显时重建
3. 落库改事件订阅者（writer）；resume 回显重做（tool 消息/摘要回显补齐——用户痛点）；老会话兼容（装饰行解析时处理）
4. TipsBar/计时数据源迁移：activityCount → 事件活动（busy 感知逻辑保留在 UI 层）
> 排期：步骤 2 验收通过后实施；老会话兼容为硬约束（存量 jsonl 必须正常回显）

### 步骤 4（分册 3：并发工具调度器）
1. CLFTool 加函数式 isConcurrencySafe（逐参数判定、fail-closed、不进工具描述）
2. 四阶段调度器：prepare（确认/守卫串行闸门——confirm 归此阶段，并发下确认天然互斥）/ dispatch（唯一并发段）/ finalize（串行）
3. 提交游标（模型序落盘，队首未完成阻塞后续提交）+ 滚动池（完成补位）+ 惰性重分类（插件热卸载安全）
4. maxParallelToolCalls 配置（默认 10，1=串行；先启动配置，热改后续评估）；取消/失败静默沿用协议闭合 + dsh 语义
> 排期：步骤 3 验收后实施；qa 对齐 dsh 测试覆盖索引（tool-calls.spec.ts 分类/屏障/模型序/滚动池/取消/静默六组）

### 步骤 5（占位册：跨进程协议与新 UI 接入——标识性占位）
1. 事件 codec 形态（JSON 序列化规则）+ 传输层（WebSocket/stdio 帧协议，dsh JSON-RPC 蓝本）
2. Qt/HTML 接入要点（订阅渲染、请求事件回传、ask_user 评估）
> 排期：**占位**。激活 = 步骤 0-4 完成 + 用户排期
