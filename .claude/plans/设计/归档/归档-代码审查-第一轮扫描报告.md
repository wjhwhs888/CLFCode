## 〇、结论速览

**全局事实（根）**：CMake 声明 clf_core 编译了 `CLFTools/CLFDiff.cpp` + `CLFFileOps.cpp`（注释："编入 clf_core 避免循环依赖"）——`CLFToolExecutor(core) → CLFFileOps/CLFDiff(tools 目录)` 反向依赖被"物理编入"绕过，**目录分层与构建分层不一致**，是后面多处问题的根。

**"雪崩"最高杠杆点不在文件行数，在三处约定缺失**：
1. **工具分类靠名字匹配**（加工具改 executor）
2. **输出接口纯虚全量实现**（加方法改 5 个类）
3. **会话策略由 UI 编排 core 原语**（加状态改 UI 多处）

先把这三处数据化/接口化，超长文件再拆不迟。

**优先级**：
- **P0（低风险高收益）**：① CLFRepl run() 拆分 ② 公共字符工具收敛 ③ SessionManager 死代码清理
- **P1（防雪崩关键）**：④ CLFTool 能力标签 ⑤ handler okJson/errJson ⑥ 会话生命周期收敛 core ⑦ ICLFOutput 默认实现规则
- **P2（结构性，需评审）**：⑧ CLFFileOps/CLFDiff 归属修正 ⑨ AgentLoop 子状态抽出 ⑩ 确认框状态机收敛

## SOLID 专项检查（2026-09-02，源码逐条核实）

### S — 单一职责原则（违反最严重）

| 类 | 职责数 | 证据 |
|---|---|---|
| **CLFAgentLoop** | ≥8 角色 | hpp 全文：HTTP 编排、会话文件状态机（7 个会话成员 m_todos/m_todoPanelDone/m_todoDirty/m_activeSessionFile/m_resumedFrom/m_historyDir/m_turnStartMsgCount）、todo 状态、摘要策略、skill 门面、安全门面、模型切换、**UI 面板开关** |
| CLFRepl::run | ~25 分支 | 780 行闭包（§1.1） |
| CLFSessionManager | 4 类 | jsonl+legacy+命名+清理（§1.3） |
| CLFToolExecutor | 3 类 | 执行+安全策略+diff 渲染（§1.5） |

**最刺眼的 S 违反**：`CLFAgentLoop::setTodoPanelDone(bool)/isTodoPanelDone()`（hpp:132-133）——**"todo 面板显示开关"是纯 UI 概念，却作为 core 类的方法**。core 类为 UI 面板状态负责 = S 违反典型。

### O — 开闭原则

**违反最重**：`CLFToolExecutor` 加新工具类型要改名字匹配（§4.1）——对扩展不开放、对修改不关闭。

### L — 里氏替换原则

**基本满足**（无继承层次滥用；CLFTool 是 struct、ICLFOutput 是接口）——低风险。

### I — 接口隔离原则

**ICLFOutput 是 god 接口**：12 纯虚 + 3 默认虚 + 2 非虚 = **17 个方法一个接口**，覆盖内容输出/状态/进度/交互/中断/思考/确认/刷新/折叠/活动计数 **10 种通道**。实现面 5 个类（1 真实 + 4 Mock），改纯虚=改 5 类。违反 I——应拆窄接口（输出 / 状态 / 进度 / 交互）。

### D — 依赖倒置原则

| 依赖 | 抽象? | 证据 |
|---|---|---|
| HTTP | ✅ 接口 | ICLFHttpClient（唯一做对的） |
| ProtocolAdapter | ❌ 具体类值成员 | hpp:195 |
| SecurityPolicy | ❌ 具体类值成员 | hpp:196 |
| Summarizer | ❌ 具体类 unique_ptr | hpp:200 |
| **UI 面板开关在 core** | ❌ core 依赖 UI 概念 | setTodoPanelDone/isTodoPanelDone（hpp:132-133） |
| CLFFileOps/CLFDiff | ❌ 反向依赖被编译绕过 | CMake 编入 clf_core |

### SOLID 结论

**CLFAgentLoop = S+D 双重违反的 god 类**（8 职责 + 依赖具体类 + 掺 UI 概念）；**ICLFOutput 违反 I**（god 接口 17 方法）；**CLFToolExecutor 违反 O**（名字匹配）；**UI 概念泄漏进 core**（todoPanelDone 是 S+D 的交叉证据）。

**新增优先级项（并入 P1/P2）**：
- P1-⑪ **UI 概念移出 core**：setTodoPanelDone/isTodoPanelDone 等面板开关应从 CLFAgentLoop 移除（改由 UI 层维护，或经接口回传）
- P2-⑫ **CLFAgentLoop 按 S 拆角色**：HTTP/会话/todo/摘要子状态抽出（呼应 ⑨，加"去 UI 概念"）
- P2-⑬ **ICLFOutput 拆窄接口**：内容/状态/进度/交互四接口，聚合实现（呼应 ⑦）

## 二、职责交叉 / 边界模糊

### 2.1 CLFTerminal vs CLFRepl — 真交叉

- 字符级处理**两侧各自实现**：cjkWidth（Terminal:198–207）vs displayWidth（SelectionModel:19–24）；ANSI 扫描（Terminal:121–159）vs CPR 剥离（Repl:183–203/822–845）
- Terminal 状态**几乎全 public**（hpp:94–126），Repl 直写 m_contentBuffer/m_confirm*/m_interruptCb（Repl:121/554–576/768/791）
- 确认对话框状态机由 Terminal::confirm + Repl 事件 + ConfirmBar **三个类手工编排**

**建议**：Terminal 状态收私有 + 窄操作（submitConfirm/cancelConfirm）；确认协议收敛 Terminal 一个类。

### 2.2 工具 handler 与 core 边界

- todo_write handler **内嵌业务状态机 + 持久化 + UI 面板语义**（直接调 setTodos/appendTodoSnapshotNow/setTodoPanelDone，BuiltinTools:218–279）——tools 越界操 core 内部
- 安全边界**同一域拆三处**：read_file 边界在 handler（BuiltinTools:138–139）、工作区检查 isWithinWorkspace 在 tools:37–61、危险命令/风险模式在 core CLFSecurityPolicy、动态升级在 CLFToolExecutor
- handler 返回 ad-hoc JSON 字符串，core formatToolResult 再解析——**跨层契约无类型**

**建议**：todo 状态机移回 core 服务方法（参照 compress_context 薄壳 581–583）；定义工具结果结构 + ok/err 封装。

### 2.3 CLFSessionManager — 混四类职责

jsonl 存储 + 遗留 JSON + 命名/title 工具 + 清理策略；list() 全量读与 loadJsonl 重复。

### 2.4 放错层的逻辑（UI↔core 双向泄漏）— 关键

- **core 做 UI 排版**：restoreSession 生成带 📋/✓/⏳ 文案并构造折叠块（AgentLoop:826–890）；finishTurn 拼"全部完成"文案（504–508）；ToolExecutor 渲染 diff（604–631）。**同一 todo 文案 UI 又写一遍**（buildTodoPanelLines, Repl:48–76）
- **UI 持有会话生命周期策略**：何时建 jsonl/追加 turn 在 CLFRepl::submit（911–988）；/clear 六步状态机在 CLFCommands:38–52；/exit 置空在 28–36；/resume 在 233–268——UI 编排 core 6+ 原语，**加状态必改这几处**
- **UI 命令做本质是服务的事**：/init 写文件（294–353）、/history 调 list 格式化（213–231）

**建议**：core 提供用例级服务（startNewSessionFile/endSessionAndSummarize/resumeTo），UI 命令变薄壳；恢复回显消费结构化行。

## 四、耦合点（防雪崩关键）

### 4.1 工具行为按名字硬编码（最高杠杆）

CLFToolExecutor 内 `== "write_file"/"edit_file"`(369/434/516/542)、`== "execute_command"`(400)、`== "web_fetch"`(416)、`name.find("search"/"read"/"list")`(373–374/591–597)。**加写类/命令类/POST 类新工具 = 改 executor 名字匹配 + 注册 + 统计**。
→ **m_concludesTurn 已有"注册期静态声明"先例（CLFTools.hpp:130），推广为能力标签**（m_writesFile/m_runsCommand/m_hasRemoteSideEffect），executor 零改动。

### 4.2 CLFAgentLoop 依赖具体类

默认构造 make_shared\<CLFHttpClient\>（:61–63）、值成员 CLFProtocolAdapter/CLFSecurityPolicy、unique_ptr Summarizer（hpp:195–200）均具体类；runTurn 每次迭代 8 参现构 CLFToolExecutor（355–357），其签名改动连锁 executor+agentloop+测试。
→ ToolExecutor 提为成员小接口化。

### 4.3 ICLFOutput 接口面

纯虚 **12 个**，**头注释仍写"6 个方法"（ICLFOutput.hpp:23）**。实现面 = CLFTerminal + **4 个测试 Mock**（qa_AgentLoop:122/qa_ToolExecutor:24/qa_Passerby:17/qa_TipsBar:21）。加纯虚=改 5 类；后加方法已自发用默认实现（setStatusKind/requestRefresh/showFoldedBlock/notifyActivity）。
→ 固化为规则"新方法必须带默认实现"；膨胀则按通道拆窄接口。

### 4.4 m_config 读取面

getConfig() 直读：Repl:430/894、Commands:108/121/139、BuiltinTools:465；main 直读字段（100–141）；AgentLoop 高频读 ~20 字段，setModelName 原地改 m_config（754–765）。config 是 CLFTypes 里"共享 god struct"。
→ 维持结构体（小型合理），但**写路径收敛**（仅 ConfigLoader/main 写，运行期只读 + 显式变更方法）。

### 4.5 会话状态跨线程锁纪律逐字段演进

m_todos 有锁/m_activeSessionFile 有锁/m_resumedFrom 无锁/m_todoPanelDone/m_todoDirty 原子（hpp:202–212 注释自证"防御性/串行"）；确认框跨 Terminal+Repl+ConfirmBar 手编 CV。
→ 会话文件状态整体封装小对象（统一锁）。

### 4.6 jsonl 行类型协议分散

type 字符串在 Codec/SessionManager/AgentLoop/测试各自出现；**加行类型需 Codec+loadJsonl+echo 三处同步**（未知类型静默跳过是唯一安全网）。
→ 类型常量集中 + 解析注册。
