## 定稿摘要（pro 先读这一页）

**一句话**：模型在 Windows 上误用 Unix 命令（`head`、`findstr -A 8`）**有两个来源**——① 提示层没告它当前平台能力边界（诱因）② **我们的失败判定给了错误信号，把它逼去重试**（真缺陷）。

| 层 | 问题 | 判定门 |
|----|------|--------|
| **信号层（P0，代码）** | 复合命令（`echo A & findstr 无匹配`）被误判为失败 → 模型以为环境坏了 → 原样重试 | 复合命令退出码 1 且末段在只读白名单 → **判成功**；qa 19 条既有断言零回归 |
| **提示层（P1，文案）** | 工具描述零平台提示（还点名 grep/rg 暗示 Unix 可用）；系统提示只有 `- Shell：cmd.exe` | 复跑同场景：不再出现 `head`；`findstr` 不再带 `-A/-B/-C`；失败后不再原样重试 |

**根因集（flash 判断）**：M1（末段语义）+ M1b（cmd 只读命令的"无匹配=正常"语义，**对 PowerShell 无效**）+ **M1c（区分"真失败"与"退出码非 0"，分开呈现）** + **M9（显示判定与 `success` 对齐）** + **M7c（PowerShell 直启、绕开 cmd 层）**。
依据：**四次独立实证**的"失败/误判 → 原样重试"（`head`、`dir`、`& "path"`、`mytoolctl`）+ **X13：修了白名单用户仍见 ✗**。
**接近根因**：M8（截断结果补"如何看完整"）、**M2/M3（提示层平台化——由 F1 "15+ 工具 / ~400k token" 与 N3 "两次试错" 实证，恢复 P1）**、M4（通用重试纪律）。
**可裁剪 / 降级**：**M7（引号包裹策略——三条 PowerShell 一行命令实测未复现，降为兜底）**、M7b、M5（`not_found` 替代建议）、M6（外部仓库文档标注，仅建议）。

## 一、问题清单（现有问题，逐条）

> 证据口径：**实测/实读** 或 **截图可见**；置信度按 §1.2 标注（高 / 中 / 强 / 未取证）。

### X1｜模型使用 Unix 命令 `head`（出现 2 次，含原样重试）

| 项 | 内容 |
|----|------|
| 现象 | `execute_command(git remote -v && echo ---- && git fetch --dry-run 2>… \| head …)` → `'head' 不是内部或外部命令，也不是可运行的程序` |
| 证据 | 用户截图（两批连续出现，命令文本相同）；报错原文为中文 cmd 文案 |
| 影响 | 命令失败；**同一命令原样重试一次**，白烧约 3.6k token（累计 2.4k → 6.0k） |
| 置信度 | **高**（报错原文 + 两次相同命令） |

### X2｜**grep 的上下文选项泄漏到 `findstr`**（静默错误，最危险）

| 项 | 内容 |
|----|------|
| 现象 | `execute_command(findstr /n /i "peerDependencies" -A 8 packages\core\…` |
| 机制 | `-A/-B/-C` 是 **grep/ripgrep 选项**；`findstr` 的选项前缀是 `/`（`/A:attr` 才是颜色），因此 **`-A` 与 `8` 会被当作额外搜索字符串** → 真实语义变成"匹配 `peerDependencies` **或** `-A` **或** `8`" |
| 影响 | ① 结果**被污染**（匹配到含 `8` 的行）② 输出量暴增 → 上下文与 token 同步膨胀 ③ **截图里这条没有 ✗**——模型拿到"成功但很怪"的结果，**比报错更难察觉** |
| 置信度 | **高**（命令原文可见；findstr 选项语义可查证） |

### X3｜**复合命令的中断码误判 —— 真缺陷（我们的代码）**

| 项 | 内容 |
|----|------|
| 现象 | `execute_command(echo ====PROFILE-BOOT==== & findstr /n /i "resolutio…")` 被标 **✗**，而其输出只是两个 echo 标记（即 `findstr` 无匹配） |
| 机制 | `exitCodeMeansSuccess(command, exitCode)`（`CLFCommandToolHandler.cpp:20-41`）只取**第一个 token**（`:24-27` `istringstream >> first`）。该命令首 token 是 `echo` → 不在白名单（`grep/rg/findstr/diff/fc`）→ 退出码 1 被判定为**失败**。而 cmd 里 `&` 复合行的退出码来自**最后一个命令**（此处是 `findstr` 无匹配 = 1，**本应视为成功**） |
| 影响 | **错误信号把模型带偏**：它把 ✗ 读成"命令/环境有问题"，于是**下一条原样重试同一条命令**（截图第 5、6 行）→ 这解释了 X4 |
| 置信度 | **高**（代码实读 + 截图时序吻合；**未实机复现**——建议 pro 用 T1 复现确认） |

### X7｜**命令包装层的引号剥离把命令劈坏**（v0.9.0 实测新抓，最严重）

| 项 | 内容 |
|----|------|
| 现象 | `✗ execute_command(powershell -NoProfile -Command "Write-Output '#### p…) — **`'ForEach-Object' 不是内部或外部命令`** |
| 机制（代码实读） | 包装为 `cmd.exe /s /c "<chcp 65001 >nul & 命令>"`（`CLFProcessRunner.cpp:243-244`）。按 cmd 规则：`/c` 后首字符是引号 → **剥掉首尾引号**。若命令**内部双引号计数为奇数**（含 PowerShell 反引号转义 `` `" ``——cmd 照数不误），剥离后引号状态**失衡** → 内部的 `\|` 被 cmd 当成**顶层管道** → `ForEach-Object` 变成一条独立命令 → 报"不是内部或外部命令" |
| 触发条件（**修正上一版过度断言**） | 不是"所有含引号都破"——**引号平衡时正常**；破的是 ① **引号计数为奇数**（含转义引号）② **命令本身以引号开头**（如 `"C:\Program Files\…\x.exe" -a`，会被当作待剥离的首引号） |
| 影响 | 命令**莫名破裂**且错误信息**指向无关对象**（报 `ForEach-Object` 而不是引号问题）→ 模型与人都难定位；属**我们的包装层引入**，非模型之过 |
| 置信度 | **中强**（代码实读 + cmd 引号规则推导 + 截图报错形态吻合；**未做最小复现**——判定实验见 审查门 4b） |

## 二、根因链

```
模型在 dsh 仓库工作（Unix-first 文档 + AGENTS.md 的 ```sh）
  → 它推断"这是 Unix 环境"                     ← X5④
  → 而提示层从未告诉它本机是 cmd.exe 及其能力边界  ← X5①②③（缺位）
  → 写出 `| head`（X1）、把 `-A 8` 塞给 findstr（X2）
  → 我们再把 `echo … & findstr 无匹配` 误判为 ✗   ← X3（真缺陷）
  → 模型把 ✗ 读成"环境/命令有问题" → 原样重试      ← X4
  → 白烧 token、用户观感"原地打转"
```

**关键判断**：**X3 是"我们的错"，X1/X2 是"提示缺位"**——两件事必须分开修，否则会出现"修了文案但模型仍被错误信号逼着重试"或"修了信号但模型继续写 `head`"。

## 三、设计原则

1. **信号必须可信**：工具结果的 ok/error 判定错了，比命令本身失败更伤——它会让模型做出错误推断（X3→X4 就是实证）。
2. **事前优于事后**：优先在**工具描述 / 系统提示**里预防，而不是等失败了再用 `errorKind` 兜（v0.9.0 的 G3 只做了事后，本文补事前）。
3. **平台条件化，不许硬编码**：所有"不支持 Unix 命令"的文案**只在 cmd/PowerShell 场景生效**——跨平台第二期到 Linux，`head/grep/sed` 反而是**正确**工具，写死会变成反向误导。
4. **动态 vs 静态分工**：平台能力（会变）放**动态注入**（`{{os_info}}`）；行为纪律（不变）放**模板**。
5. **零行为变更优先**：M1 只改函数内部，签名与既有断言保持；M2/M3 只改文案与取值方式。

## 四、方案（M1–M6）

### M1｜`exitCodeMeansSuccess` 按 cmd 语义取**末段**（P0，代码）

- **位置**：`src/CLFTools/CLFCommandToolHandler.cpp:20-41`（共享实现；`CLFBuiltinTools.cpp:51-52` 的 `detail::` 转发钉子**签名不变**）。
- **改法**：新增内部 helper `effectiveSubCommand(command)`，取**最后一个顶层子命令**，再套现有的"去引号 → 去路径 → 去扩展名 → 转小写 → 白名单"归一化。
- **分隔符识别（关键，必须防误切）**：
  - 顶层分隔符：`&&`、`||`、`|`、`&`
  - **必须排除**：重定向形式 `2>&1`、`1>&2`、`>&2`（其中的 `&` **不是**分隔符）；双引号内的分隔符；cmd 转义 `^&`
  - **不确定即保守**：出现未闭合引号等无法安全切分的情形 → **回退到今天的行为**（首 token），不猜
- **语义确认（flash 判断，请 pro 复核）**：cmd 中 `a & b` 的退出码 = **b** 的退出码；`a && b` 的退出码同为末段（`b` 未执行时取 `a`）。因此"退出码 1 是否算成功"必须看**末段**。
- **不做**：不给 `echo` 之类加白名单（那是**表修**——`echo` 正常不返回 1，1 来自后面的 `findstr`；加白名单会掩盖真失败）。

### M1b｜白名单补 Windows 原生只读命令（P0，代码；**与 M1 同批**）

- **位置**：同 M1（`CLFCommandToolHandler.cpp:20-41` 的白名单判定）。
- **改法**：把"无匹配 = 正常"的 Windows 原生命令纳入白名单，至少 **`dir` / `where` / `find`**（`findstr`/`fc` 已有）。
  - 语义说明：`dir *.js` 无匹配 → 1；`where xxx` 未找到 → 1；`find "x" f` 无匹配 → 1——**都是"正常答案"**。
  - **`type` 建议不加**：`type notexist.txt` 的 1 是**真失败**（精确路径不存在）——与通配语义不同。
- **信息不丢**：结果 JSON 里**保留 `exitCode` 与原始 stderr**（已有），模型仍能看到真实退出码——白名单只影响 ok/error 判定。
- **附**：`dir` 真失败（如 `dir Z:\nope`）也会返回 1 → 同样会被视为"正常"。**flash 判断：此误判可接受**（模型看得到空输出 + exitCode=1；比"无匹配被报错"的误导更轻）。**请 pro 复核该取舍**。

### M1c｜区分"真失败"与"退出码非 0"（P0，代码 + 呈现）

- **问题**：`powershell -Command "..."` 这类命令**大量出现在模型侧**，其退出码语义**属脚本级、无法用白名单枚举**。实测中 `Get-Command ffmpeg`（未装）、`Get-ChildItem 'C:\Pr…'`（无匹配）都是 **exit 1 → 被标 ✗**，而它们**都是正常答案**。
- **改法（**flash 判断，请 pro 复核**）**：把命令结果分两档呈现，而不是一律 ✗：
  | 档 | 判据 | 呈现 |
  |----|------|------|
  | **真失败** | 启动失败（`not_found`/`permission`/`launch_failed`）或 `bad_quoting`；超时；被中断 | **✗ 失败** |
  | **执行了但退出码非 0** | 命令正常启动、未超时、`errorKind` 为 `non_zero_exit` | **中性/⚠ + 明示退出码**（让模型看输出判断，而不是被"失败"二字误导） |
- **理由**：模型对 ✗ 的默认反应是**重试同一条**（四次实证）；把"语义正常"和"真失败"混成一个符号，是**信号设计**的问题，不是模型的问题。
- **不做**：不试图枚举所有"无匹配=正常"的命令（枚举不完，且 PowerShell 脚本不可判定）。

### M7c｜**PowerShell 直启：绕开 cmd 层**（P0，代码；X16/X7 族的根修）

- **现状**：所有命令统一走 `cmd.exe /s /c "<chcp … & 命令>"`（`CLFProcessRunner.cpp:243-244`）→ cmd 先解释 `>`、`|`、`&`，导致 PowerShell 脚本里的元字符**被截胡**（X16 的垃圾文件、X7 的 `&` 报错）。
- **改法**：当命令**首 token 是 `powershell` / `pwsh`** 时，**以 argv 模式直启该解释器**（把 `-NoProfile`/`-Command` 等开关与脚本原样交给它），**cmd 完全退出链路**。
  - 复用 v0.9.0 已落地的 `m_argv` 双模基础设施 → **不需要新机制**；
  - 效果：`|`、`&`、`>`、引号**全部由 PowerShell 自己解释** → **X16 与 X7 这一族整类消失**。
- **风险/边界（请 pro 评估）**：① 轻量解析开关（`-NoProfile`/`-NoLogo`/`-Command`/`-File`）的边界；② 畸形混写（`powershell … ; cmd /c …`）如何降级到 shell 模式；③ 解析失败时的**回退策略**（回退到 cmd 包装，保持老行为）。
- **验收**：T17/T18（含 `|`/`{}`/`>` 的 PowerShell 脚本 → 无"不是内部或外部命令"、**工作区无新增文件**）。

### M7｜包装层引号策略（**P2 兜底**，代码；X7 实测未复现）

> 若 M7c 落地，本节降为**兜底**（非 PowerShell 命令的引号边界）；保留原因见 X7 的触发条件分析（引号奇数 / 首引号）。

- **位置**：`src/CLFTypes/CLFProcessRunner.cpp:243-244`（shell 模式包装）。
- **现状**：`cmd.exe /s /c "<wrapped>"`——无条件用一对引号包整条命令。
- **改法（按 X7 触发条件分流）**：
  1. **命令首字符不是 `"`** → **不加外层引号**：`cmd.exe /s /c <wrapped>`（让 cmd 按命令自身的引号状态处理；我们不再"多剥一层"）
  2. **命令首字符是 `"`** → 用标准双引号包裹法：`cmd.exe /s /c ""<wrapped>""`（首尾各两个引号，cmd 剥掉最外层后留下原本的首尾引号）
  3. `chcp 65001 >nul & ` 前缀照旧
- **不改**：管道读取、Job Object、取消检查、限额截断（v0.9.0 已落地部分）。
- **注意**：**引号计数为奇数**的情形（模型自己写坏了引号）**无法靠包装修复**——那时 `|` 泄漏是 cmd 的固有行为；改由 M7b 兜。

### M7b｜引号预检：把"莫名报错"换成"可读错误 + 替代建议"（P0，代码，可选但强烈建议）

- **做法**：执行前扫描命令，**统计未被转义的双引号个数**；若为奇数 → **不执行**，直接返回结构化错误：
  ```
  命令中的双引号不配对（奇数个）：外层 shell（cmd）会把 | 和 & 当成顶层分隔符，导致脚本被劈开。
  建议：改用单引号包裹参数、或把脚本写成一行不带嵌套引号的写法、或改用 -File 执行脚本文件。
  ```
  `errorKind` 可用 `platform_mismatch` 或新增 `bad_quoting`（**枚举扩张需 pro 定**）。
- **价值**：把 X7 那种"报 `ForEach-Object` 不是命令"的**误导性失败**，变成**指向真因的可操作提示**——确定性纠偏，不依赖模型自觉。



### M2｜工具描述平台条件化（P1，文案；**已因 v0.9.0 实测降级为待冷启动复现**）

- **文案见 §五**（Windows 版 / 非 Windows 版）。

### M9｜**显示判定与 `success` 对齐**（P0，代码；**建议下沉 ctest**）

- **位置**：`src/CLFCore/CLFToolExecutor.cpp:62-75`（`formatToolResult` 的 `exitCode` 分支）。
- **现状**：`if (r.contains("exitCode")) { if (code == 0) ok; else 失败 }` → **完全忽略 `success`/`errorKind`**。
- **后果（X13）**：白名单判成功（`success=true`）、模型看到成功，**用户仍看到 ✗** → 观感与事实分叉；用户会像这次实测一样继续报"✗ 有问题"，而实际是显示规则没跟上。
- **改法**：显示判定以 **`success`** 为准（`exitCode` 作为**附注信息**展示）；`errorKind` 参与呈现档位（与 M1c 的"两档"一致）。
- **测试归属**：这是"给定输入 → 确定输出"，**必须用 ctest 覆盖**（T16），不要靠 AT/人工发现。

### M5｜`not_found` 时追加替代建议（P2，可选/可裁剪）

- **位置**：`CLFCommandToolHandler.cpp` 的结果 JSON（或 `CLFProcessRunner` 的 errorKind 归一后，由 handler 追加）。
- **做法**：当 `errorKind == "not_found"` 且命令首 token 命中**已知 Unix-ism 表**时，在结果里追加一行"本平台替代写法"：

| Unix | Windows 替代 |
|------|--------------|
| `head` / `tail` | **无需**——工具输出已自动保留头尾；需要分页用 `more` |
| `grep` | `findstr`（**无 `-A/-B/-C`**） |
| `ls` / `cat` | `dir` / `type` |
| `sed` / `awk` | `powershell -Command "…"` |
| `rm` / `cp` / `mv` | `del` / `copy` / `move` |
| `xargs` | `for /f` |

- **理由**：这是**确定性纠偏**（不依赖模型自觉），且成本低。
- **可裁剪**：若 pro 认为 M2/M4 已足够，可砍；砍后请说明（写入 §十二）。

## 十、已知边界与不做的事

- **不做**：给 `echo` 等加白名单（表修，会掩盖真失败）。
- **不做**：把 Unix 命令"翻译"成 Windows 命令后自动执行（魔法，且语义不等价）。
- **不做**：修改 dsh 仓库文档（外部项目；仅建议其标注 `[Linux/macOS]`）。
- **平台条件**：所有"不支持 Unix"文案**只在 cmd/PowerShell 场景注入**——第二期 Linux 上反过来。
- **已知不可修**：若用户本机真的装了 Unix 工具（Git for Windows 的 `grep.exe` 等），模型用它们**不一定是错**——故文案写"默认没有"，而不是"禁止使用"。
