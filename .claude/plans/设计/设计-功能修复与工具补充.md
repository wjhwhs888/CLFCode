### 📌 两阶段的关系（重要）

1. **A 阶段的产出在 B 阶段不会白做**——方案 A 是**双后端并存**：dsh 不可用时自动降级到直连后端。直连后端永远是兜底路径，因此 A 阶段的安全加固、工具补充、摘要、多模型全部长期有效。
2. **A 阶段不依赖 B 阶段的任何前置**，可立即开工。
3. **B 阶段强烈建议在 A 阶段之后**：A 做完才能把决策门的问题收敛成"只剩 subagent"这一个问题；否则会为了 todo/压缩/多模型这些**自研 1 天就有**的能力去背 8.5-12.5 天的接入成本。

- **现状**：`CLFFileOps::editFile`（`CLFFileOps.cpp:205-262`）无空串校验。`content.find("")` 命中 `0..size` 每个位置，计数循环（`:230-237`）恰好计出 `size()+1` 次匹配，唯一性检查失效且空转。handler 侧（`CLFBuiltinTools.cpp:85-106`）与 `CLFToolExecutor.cpp:141-149` 的 previewEdit 同样不校验

- **文件**：`src/CLFTools/CLFFileOps.cpp`
- **验证**：`edit_file(old_string="")` 立即返回明确错误，无空转

### S1-2. write_file force 文案修正

- **现状**：`CLFToolExecutor.cpp:411-419` 文案为 `"File too large to preview diff. Use Auto mode or set force=true."`，但 write_file schema（`CLFBuiltinTools.cpp:177-184`）仅有 `path`/`content`，无 `force`（edit_file 同样没有）——模型无法传，纯误导
- **设计**：文案改为 `"File too large to preview diff. Use Auto mode."`（去掉 force 引用）
- **文件**：`src/CLFCore/CLFToolExecutor.cpp`
- **说明**：完整方案（schema 增 force 参数，语义="用户已显式同意"，仅跳过工具层确认、不绕过全局安全模式）列入 S4，本批只做文案

### S1-3. 重试策略分级

- **现状**：`CLFRetryPolicy::isFatalHttpError`（`CLFRetryPolicy.cpp:7-13`）仅 400/401/402/403 致命；`kMaxRetries = 3`（`CLFRetryPolicy.hpp:15`）。`CLFAgentLoop.cpp:223,276` 用 `++consecutiveErrors >= kMaxRetries`，实为最多 3 次总尝试（2 次重试）。404/405/409/413/422 等请求自身错误被无谓重试
- **设计**：拆分为两个判定函数 + **按类控制总尝试次数**
  | 状态码 | 行为 | 最大总尝试 |
  |---|---|---|
  | 400,401,402,403,404,405,409,413,422 | 致命，不重试 | 1 |
  | 429、5xx、超时/连接失败 | 可重试 | 3 |
  | 其他 4xx | 重试 1 次后放弃 | **2** |
  - **调用约定**：`CLFRetryPolicy` 增 `maxAttemptsForError(err)` 返回上表"最大总尝试"；`CLFAgentLoop` 的 `++consecutiveErrors >= kMaxRetries` 改为 `>= maxAttemptsForError(response.m_error)`（fatal 分支维持直接返回，其余按分类上限判定）
- **文件**：`src/CLFCore/CLFRetryPolicy.{hpp,cpp}`、`CLFAgentLoop.cpp`（错误分支改用新函数）
- **验证**：`qa_` 新增状态码分类用例（fatal / 429·5xx / 其他 4xx 三类）

### S1-4. m_wasAborted 接线

- **现状**：`CLFHttpClient::abort()`（`CLFHttpClient.cpp:156-162`）仅设 `m_aborted = true` + `m_activeCli->stop()`；`m_wasAborted` 全库无赋值点，`CLFAgentLoop.cpp:212`（流式）与 `:266`（同步）的中断分支恒 false，形同虚设（主路径靠 `m_interrupted` 兜底，可工作但语义不清）

### S2-1. read_file 边界检查 + 大小上限 + 行范围【合并 P2-1 + T7】

- **现状**：`readFileHandler`（`CLFBuiltinTools.cpp:43-61`）直接调 `CLF::CLFTools::readFile(path)`，无工作区边界检查、无大小上限（`CLFFileOps.cpp:158-173` 用 rdbuf 全量读入）。可读工作区外任意路径含敏感文件，超大文件撑爆内存
- **设计**（三合一，一次改完同一 handler）：
  1. **边界校验**：工作区根 = `CLFConfigLoader::getWorkingDir()`；路径规范化（`weakly_canonical`）后须位于工作区内，区外绝对路径拒绝并返回明确错误
     - ⚠ 实现要求：用 `canonical`/`weakly_canonical` **跟随 junction/symlink 解析**（防符号链接指向区外逃逸）；同时明确语义——"工作区 = cwd"，用户从任意目录启动时边界即该目录（`allow_absolute_read` 逃生口兜底）
     - 例外开关：配置项 `allow_absolute_read`（默认 false）
  2. **大小上限**：50MB，超限拒绝（与 search 的 1MB 分开）
  3. **行范围**：schema 增 `offset`（起始行，默认 0）、`limit`（最大行数，默认全部）
- **文件**：`src/CLFTools/CLFFileOps.cpp`、`src/CLFTools/CLFBuiltinTools.cpp`
- **验证**：读工作区内正常；读 `C:\Windows\...` 拒绝；>50MB 拒绝；offset/limit 正确切片

### S2-2. 命令危险模式检测【P2-2】

- **现状**：`CLFCommandExec.cpp`（36-207 行）无任何危险命令检测，仅 clamp 超时 + `cmd.exe /s /c` 执行；`CLFSecurityPolicy.cpp:25-49` 纯按"风险级 + 模式"放行，不看命令文本。Auto 模式下全放行
- **设计**：在 `CLFCommandExec` 内加**静态危险模式检测，不受安全模式影响**
  - 匹配（大小写不敏感、去引号后）：`rm -rf`、`format`、`del /s`、`del /q`、`rd /s`、`Remove-Item -Recurse`、`git push --force`、`git reset --hard`、`shutdown`、`diskpart`
  - 命中 → 强制 `needConfirm = true`，即使 Auto 模式
  - 白名单：配置项 `command_allowlist`（前缀匹配，默认空），命中则跳过检测
  - ⚠ **定位说明**：这是**提示层**而非安全边界——模型可构造绕过写法（变量拼接/中间命令），检测仅用于降低误操作概率，不替代安全模式
- **文件**：`src/CLFTools/CLFCommandExec.{hpp,cpp}`、`src/CLFCore/CLFToolExecutor.cpp`（风险升级路径）
- **验证**：Auto 模式执行 `rm -rf /` 触发确认；白名单命令直接放行

### S2-3. execute_command 增强【合并 P2-9 + T8】

- **现状**：`CLFBuiltinTools.cpp:136` `result["success"] = (cmdResult.m_exitCode == 0)`，全库无白名单机制。`grep`（无匹配=1）、`diff`（有差异=1）被误判为失败。无 cwd/env 参数
- **设计**（同一 handler 一次改完）：
  1. **退出码白名单**：解析 command 首 token → 查表覆写判定
     | 命令前缀 | 退出码 1 | 判定 |
     |---|---|---|
     | grep, rg, findstr, diff, fc | 1 | 成功（输出即结果） |
     | 其他 | 非 0 | 失败 |
  2. **cwd 参数**：可选工作目录（须在工作区内，复用 S2-1 的边界校验；**仅约束 cwd 参数本身，命令文本内的 `cd` 不受限**）
  3. ~~**env 参数**~~ → **移入 S4**（2026-08-25 实施时决定）：Windows 需 `GetEnvironmentStrings` 取现有环境、解析、合并、构造双 null 结尾的环境块传给 `CreateProcess` 的 `lpEnvironment`；POSIX 侧现有实现是 `fork + sh -c` 重定向，也需另行处理。两边合计约 60-80 行，而模型可用 `set VAR=x && cmd`（Windows）/ `VAR=x cmd`（POSIX）变通达成同等效果，收益不足以支撑该复杂度
- **文件**：`src/CLFTools/CLFBuiltinTools.cpp`、`src/CLFTools/CLFCommandExec.{hpp,cpp}`
- **验证**：`execute_command("grep x file")` 无匹配返回成功且输出为空；cwd/env 生效

### S2-5. web_fetch 网络工具【合并 P3-1 ≡ T1】

- **现状**：模型完全无法访问网络。⚠️ **`CLFHttpClient` 不可直接复用**（见 §2.3 修正 ⑤）：只有 POST 无 GET、恒带 `Authorization: Bearer <apiKey>`、baseUrl 单主机模型
- **设计**：**新建独立轻量 HTTP 封装**（httplib 依赖已就位，OpenSSL 已链接）
  - 新增 `src/CLFTools/CLFWebFetch.{hpp,cpp}`，**不复用 CLFHttpClient，不携带任何凭据头**
  - 参数：`url`、`method`（默认 GET，支持 GET/POST/HEAD）、`headers`（可选对象）、`body`（可选）、`timeout`（秒，默认 15，上限 60）
  - 返回：`{status, headers(截断), body(截断)}`
  - 约束：响应读取上限 1MB；body 截断 head 8KB + tail 2KB；二进制检测（NUL 字节）→ 返回"二进制内容，已跳过"
    - ⚠️ **`headTailCapWithMarker` 不可直接复用**（08-25 核实）：其签名为 `template<T> std::vector<T> headTailCapWithMarker(const std::vector<T>&, const T& marker, size_t n = 16)`（`CLFTypes.hpp:179-180`），按 **vector 元素个数**截断，而此处需 **字节数**（8KB/2KB）截断字符串。二者语义不同 → **新写字节级截断助手**（注意 UTF-8 边界安全，可参照 `CLFSessionManager` 标题截断的既有做法）
  - 风险级（**安全定级**，08-25 二复审）：
    - **GET / HEAD = Read**，但"外联"≠"本地读"——GET 可携带参数外发本地信息，**Analyze 模式下仍需确认或阻断**（防数据外泄）；SSRF 不做地址限制（本地场景允许内网，由安全模式兜底）
    - **POST = Command 级**（远端副作用）：强制 `needConfirm`，即使 Auto 模式
- **文件**：新增 `CLFWebFetch.{hpp,cpp}`；`CLFBuiltinTools.cpp` 注册；`src/CMakeLists.txt` 加入 `clf_tools`
  - ⚠ **链接说明**：clf_tools 内 httplib SSL 需 OpenSSL 符号——主程序 CLFCode 已链 `${CLF_OPENSSL_LIBS}` 可解析；若后续为 web_fetch 编写**只链 clf_tools 的单测目标**，需补 OpenSSL 链接（静态库按需拉取对象，现状无碍，实现时注意）
- **验证**：抓公网页面返回文本；超时/404 明确错误；二进制正确跳过；**断言请求头不含 Authorization**；qa 用例（本地起 mock HTTP 服务）
