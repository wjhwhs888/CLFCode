## 三、设计（v2）

### 3.1 捕获层：双拼写归一解析（两处同构）

解析顺序（dsh 同构）：`prompt_tokens_details.cached_tokens`（OpenAI 兼容）优先，`prompt_cache_hit_tokens`（DeepSeek 原生）兜底。照既有"缺失保持原值——不估猜"哲学。

**① `CLFStreamAccumulator::feedUsage`（流式）**
```cpp
// 缓存命中 token：OpenAI 兼容拼写优先，DeepSeek 原生拼写兜底（dsh translate.ts 同构）
if (usage.contains("prompt_tokens_details") && usage["prompt_tokens_details"].is_object()
    && usage["prompt_tokens_details"].contains("cached_tokens")
    && usage["prompt_tokens_details"]["cached_tokens"].is_number())
    m_usageCacheHit = usage["prompt_tokens_details"]["cached_tokens"].get<int>();
else if (usage.contains("prompt_cache_hit_tokens") && usage["prompt_cache_hit_tokens"].is_number())
    m_usageCacheHit = usage["prompt_cache_hit_tokens"].get<int>();
```

**② `CLFProtocolAdapter::parseAssistantResponse`（同步）**：同逻辑 → `CLFAssistantResponse::m_usageCacheHit`。

### 3.2 累计层：独立类 `CLFSessionUsage`（会话累计）

**为何独立成类**：累计 + 百分比是内聚职责簇（纯逻辑零依赖），放 AgentLoop 与 C2 拆角色方向（P1-1 god 类治理）背道而驰。捕获层两处解析刻意不抽（CCP：usage 字段与既有三字段因同一原因——provider 协议变更——变化，留原类）。

**`src/CLFTypes/CLFSessionUsage.hpp`**（header-only，零 CMake 源改动）：
```cpp
// CLFSessionUsage.hpp — 会话 usage 统计（缓存命中率的累计与文案）
class CLFSessionUsage {
public:
    void accumulate(int promptTokens, int cacheHitTokens);
    // gate：prompt>0 且 cacheHit>0 才返回非空（无 usage 数据/零命中不显示，不宣称 0%）
    // 防虚报：cacheHit>=prompt → 100，否则 floor 永不四舍五入
    std::string percentText() const;
private:
    int m_promptTokens = 0;
    int m_cacheHitTokens = 0;
};
```

**AgentLoop 接线**（仅持实例 + 累计，零逻辑）：
- 成员 `m_sessionUsage`（hpp m_totalTokensUsed 旁）+ 公共 getter `getSessionUsage()`（const& 返回，UI 渲染读）
- **累计**：R3 gate 内 `m_sessionUsage.accumulate(parsed.m_usagePrompt, parsed.m_usageCacheHit);`——仅正常解析路径累计（R3 同规则）；**无 reset**（与 m_totalTokensUsed 同生命周期）
- 精度：触顶 wrapUp（独立同步调用）不走 R3 累计点 → 不计入（既有行为，不修正）

### 3.3 显示层：底部常亮参数行（modeLine）

**落点**：`CLFReplView.cpp` modeLine——会话级参数常亮行（模型名/目录/安全模式同列），dsh 会话统计面板的终端对应物。位置：安全模式段之后、"Shift+Tab 切换"之前：

```
deepseek-v4-flash │ 📁 CLFCode │ 🔒 edit │ ⚡缓存命中 75%  Shift+Tab 切换      /help 帮助
```

**实现**（每帧渲染读值，值变自动刷新）：
```cpp
const std::string cacheHitText = m_agent.getSessionUsage().percentText();
ftxui::Element cacheHitEl = ftxui::emptyElement();  // 无数据 → 零占用
if (!cacheHitText.empty()) {
    cacheHitEl = ftxui::hbox({
        sep(),
        ftxui::text(" ⚡缓存命中 " + cacheHitText + "%") | ftxui::dim,
    });
}
```

**与对话流的关系**：缓存文案**不进对话流**（不 emitContent、不进 finalContent）——天然不污染模型上下文（v1 的 addMessage 避让问题在 v2 架构下消失）。

### 3.4 边界与防御

| 场景 | 行为 |
|---|---|
| 非 deepseek provider（无 include_usage） | usage 未到达 → gate 不显示，零回归 |
| 真实零命中（cacheHit=0 合法） | 不显示（不宣称 0%） |
| 异常数据 cacheHit > prompt | clamp 100%（`>=` 判定） |
| 中断/错误回合 | R3 gate 前 return → 不累计（T10b 钉死） |
| 触顶收尾请求（wrapUp） | 不走 R3 累计点（既有行为）→ 不计入；不修正 |
| /clear 新会话 | 累计保持（与 m_totalTokensUsed 同生命周期，既有 /context 口径一致） |
| 渲染线程竞争 | 无锁值读（m_totalTokensUsed 同模式），撕裂至多旧值一帧 |
| 老会话 / jsonl | 格式零改动 |

## 九、变更历史

| 时间 | 变更 |
|---|---|
| 2026-09-08 v1 | 初版：回合收尾统计行（finishTurn/触顶两出口 emit）——已实施后**被 v2 取代**（回退：appendCacheHitLine helper 与两处调用删除；CLFTurnUsage displayLine 块状文案删除） |
| 2026-09-08 v2 | 用户需求变更："底部常亮显示…统计这一轮会话的值…类似 dsh…作为当前会话的缓存命中率参数"→ modeLine 常亮 + 会话累计（类重命名 CLFTurnUsage→CLFSessionUsage，reset 删除，percentText 替代 displayLine） |

**v1→v2 关键差异**：
- 口径：回合累计（runTurn 入口 reset）→ 会话累计（与 m_totalTokensUsed 同生命周期不重置）
- 显示：对话流收尾行（双通道 emit/返回值）→ modeLine 常亮段（渲染线程每帧读，无对话流污染问题）
- 触顶路径：v1 需单独接线（触顶不走 finishTurn）→ v2 无此问题（累计在 R3 gate 统一，显示在 UI 统一）
