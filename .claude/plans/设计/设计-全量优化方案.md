# CLFCode 全量优化方案

## Context

项目功能已完整（所有待做项 ✅），当前处于质量提升阶段。经三个维度全面审计（SOLID+职责拆分、依赖+编译耦合、错误处理+测试+性能），发现以下核心问题需优化。

审计报告来源（3 个并行 Agent 分析，2026-08-03）：
- 大文件职责拆分 + SOLID 原则审计
- 头文件依赖图 + 编译耦合 + 平台/第三方依赖隔离
- 错误处理审计 + 测试覆盖 + 性能热点识别

---

## 一、总体策略

分 4 个阶段，按**风险 → 耦合 → 整洁 → 覆盖**顺序推进：

| 阶段 | 主题 | 优先级 | 涉及文件数 | 风险 |
|------|------|--------|-----------|------|
| P0 | Bug 修复（崩溃/UB/数据竞争） | 🔴 紧急 | 5 | 无（纯修 bug） |
| P1 | 架构解耦（类型提取 + 头依赖治理） | 🟡 高 | 12+ | 低（机械重构） |
| P2 | 大文件拆分 + 错误处理加固 | 🟢 中 | 8 | 中（新文件） |
| P3 | 测试补充 + 性能微调 | 🔵 低 | 5+ | 低 |

## 二、P0：Bug 修复（5 项）

### 2.1 [P0-1] CLFCommandExec 超时 detach 悬垂引用（UB/崩溃）
- **文件**: `src/CLFTools/CLFCommandExec.cpp:110-111`
- **问题**: `cmdThread.detach()` 后线程持有 `[&]` 捕获的栈变量引用，函数返回后读写已析构对象
- **修复**:
  - 用 `std::atomic<bool>` + `std::thread` + `join()` 替代 detach
  - 或用 `CreateProcess` + `WaitForSingleObject(timeout)` 替代 `std::system`，超时时 `TerminateProcess`
  - 临时文件加随机后缀防冲突，超时后轮询等进程退出再清理

### 2.2 [P0-2] CLFHttpClient::m_activeCli 非 RAII 泄漏
- **文件**: `src/CLFNetwork/CLFHttpClient.cpp:116-119`
- **问题**: 回调 `onLine` 若抛异常，`m_activeCli.reset()` 不执行，后续 `abort()` 访问已析构 Client → UB
- **修复**: 用 RAII 守卫（`std::shared_ptr` 自定义 deleter 或 scope_exit）确保 m_activeCli 清理

### 2.3 [P0-3] 序列化 dump() 无异常保护 → std::terminate
- **文件**: `src/CLFCore/CLFContext.cpp:164`、`src/CLFCore/CLFSessionManager.cpp:132`
- **问题**: `json::dump()` 对无效 UTF-8 抛异常，CLFRepl::run() 无兜底 catch → 进程崩溃
- **修复**:
  - dump() 外包裹 try/catch(json::exception)，失败时用 `error_handler_t::replace` 降级
  - CLFRepl::run() 主循环外包 try/catch(...) 兜底（保底措施）

### 2.4 [P0-4] m_escPressed 非原子跨线程读写（数据竞争）
- **文件**: `src/CLFCore/CLFAgentLoop.cpp:65/181`
- **问题**: ThinkingIndicator 后台线程写、主线程读，非原子 → UB
- **修复**: `bool m_escPressed` → `std::atomic<bool> m_escPressed`

### 2.5 [P0-5] CLFTerminal::s_scrollBuffer 无锁并发读写（数据竞争）
- **文件**: `src/CLFCore/CLFTerminal.cpp:21-30`
- **问题**: HTTP 流式回调线程 push_back，主线程读取/清空，无锁
- **修复**: 加 `std::mutex` 保护 s_scrollBuffer 的读写

## 三、P1：架构解耦（5 项）

### 3.1 [P1-1] 抽取 CLFTypes.hpp — 类型归属归位
- **新建文件**: `src/CLFCore/CLFTypes.hpp`（零 include，纯数据定义）
- **内容**:
  - `CLFAgentConfig` 结构体（从 `CLFAgentLoop.hpp` 移出）
  - `CLFTool` + `CLFToolCall` + `CLFToolResult` 结构体（从 `CLFAgentLoop.hpp` / `CLFContext.hpp` 移出）
  - `CLFMessage` + `CLFRole` + `CLFHttpResponse`（从 `CLFContext.hpp` 移出）
- **收益**:
  - `CLFConfigLoader.hpp` 不再需要 include `CLFAgentLoop.hpp`（砍掉最重的头依赖）
  - `CLFProtocolAdapter.hpp/cpp` 不再反向 include `CLFAgentLoop.hpp`（消除编译级环形依赖）
  - `CLFBuiltinTools.cpp` 等工具层只依赖轻量类型头

### 3.2 [P1-2] 消除 CLFCore → CLFNetwork 头文件依赖
- **文件**: `src/CLFCore/CLFAgentLoop.hpp:14`
- **改动**: `#include "CLFNetwork/CLFHttpClient.hpp"` → 前向声明 `namespace CLF::CLFNetwork { class ICLFHttpClient; }`
- **理由**: `m_httpClient` 是 `shared_ptr<ICLFHttpClient>`，shared_ptr 支持不完整类型
- **收益**: CLFHttpClient.hpp 的编译影响从 9 个单元降到 2 个
- **附带**: CMakeLists.txt 补充 `clf_core` → `clf_network` 链接依赖声明

### 3.3 [P1-3] nlohmann/json 从头文件驱逐
- **涉及文件**:
  - `CLFStreamAccumulator.hpp:16` — 把 inline 实现移到新的 `CLFStreamAccumulator.cpp`
  - `CLFProtocolAdapter.hpp:14` — 把 `serializeMessage`/`serializeToolDefinition` 改为 `.cpp` 匿名命名空间自由函数
- **收益**: json 不再通过头文件泄漏到全项目，只留在 5 个直接使用它的 .cpp 中

### 3.4 [P1-4] 消除冗余 include（前向声明替代）
- **CLFRepl.hpp:13**: `#include "CLFCore/CLFAgentLoop.hpp"` → `class CLFAgentLoop;`（成员是引用 `CLFAgentLoop&`）
- **CLFConfigLoader.hpp:13**: `#include "CLFCore/CLFAgentLoop.hpp"` → `struct CLFAgentConfig;`（P1-1 后自动解决）
- **CLFLogger.cpp:13**: 移除未使用的 `#include <windows.h>`

### 3.5 [P1-5] CMake 链接依赖修正
- **文件**: `src/CMakeLists.txt`
- **改动**: `target_link_libraries(clf_core PUBLIC clf_network)`（当前 CLFAgentLoop.cpp 构造 CLFHttpClient 但未声明链接依赖）

## 四、P2：大文件拆分 + 错误处理加固（6 项）

### 4.1 [P2-1] CLFAgentLoop 拆分（560 行 → ~200 行核心 + 4 个新文件）
- **拆出 CLFToolExecutor** (`src/CLFCore/CLFToolExecutor.hpp/cpp`):
  - `executeTools()` + `extractKeyParam()` / `formatToolResult()` + 安全确认 + 结果格式化
- **拆出 CLFStreamProcessor** (`src/CLFCore/CLFStreamProcessor.hpp/cpp`):
  - SSE 流式解析 + `CLFStreamAccumulator` 所有权
- **拆出 CLFThinkingIndicator** (`src/CLFCore/CLFThinkingIndicator.hpp/cpp`):
  - 后台线程 + ESC 检测
- **拆出 CLFRetryPolicy** (`src/CLFCore/CLFRetryPolicy.hpp/cpp`):
  - 错误分类 + 退避重试（同步将字符串匹配改为结构化错误码）
- **CLFAgentLoop 保留**: 编排骨架 + 工具注册门面 + 系统提示注入

### 4.2 [P2-2] CLFRepl 拆分（457 行 → ~150 行核心 + 2 个新文件）
- **拆出 CLFCommandDispatcher** (`src/CLFCore/CLFCommandDispatcher.hpp/cpp`):
  - 命令注册表 `std::map<std::string, CommandHandler>`
  - 10 个命令 handler，新增命令只需注册（OCP）
- **拆出 CLFConfirmDialog** (`src/CLFCore/CLFConfirmDialog.hpp/cpp`):
  - 确认交互逻辑（上下键选择）
- **CLFRepl 保留**: 按键主循环 + submit + 布局初始化 + 模式切换
- **附带清理**: 删除 `handleKey()` 死声明

### 4.3 [P2-3] CLFTerminal 职责分离（486 行 → ~250 行 + 2 个新文件）
- **拆出 CLFAnsi** (`src/CLFCore/CLFAnsi.hpp/cpp`):
  - ANSI 颜色 ×8 + 树状输出 + 终端尺寸原语
- **拆出 CLFScrollBuffer** (`src/CLFCore/CLFScrollBuffer.hpp/cpp`):
  - 滚动区内容缓冲（线程安全，P0-5 同步修复）
- **CLFTerminal 保留**: 五区布局状态机
- **附带清理**: 删除 `setScrollCollapsed`/`isScrollCollapsed` 空实现和 `s_scrollCollapsed` 死状态

### 4.4 [P2-4] 错误处理加固 — 结构化错误码
- **新建**: `src/CLFCore/CLFErrorCodes.hpp`（枚举 `CLFError`）
- **改造文件**:

  - `CLFAgentLoop.cpp`: 字符串子串匹配错误分类 → 枚举匹配
  - `CLFProtocolAdapter.cpp`: 异常捕获改为返回 error 标记（不抛）

### 4.5 [P2-5] 平台抽象层（可选）
- **新建**: `src/CLFPlatform/CLFPlatform.hpp` + `CLFPlatformWin.cpp` + `CLFPlatformUnix.cpp`
- 集中管理 `terminalSize()` / `rawInput()` / `toUtf8()` / `createProcess()` / `getExecutablePath()`
- 消除 7 处 `#ifdef _WIN32` 分散条件编译

### 4.6 [P2-6] 消除重复代码
- **CLFEncoding**: 合并 `CLFFileOps::toUtf8` 和 `CLFCommandExec::toUtf8` → `src/CLFCore/CLFEncoding.hpp/cpp`
- **CLFMessageCodec**: 合并 `CLFContext::serialize/restore` 和 `CLFSessionManager` 的 JSON 序列化重复
- **CLFBuiltinTools 样板消除**: 5 个重复 try/catch 模式 → `CLFJsonToolResult` 模板

## 六、实施顺序

```
P0-1 (命令执行UB)  ──┐
P0-2 (HTTP RAII)   ──┤ 第一批：无依赖，独立修复
P0-4 (原子bool)    ──┤
P0-5 (终端加锁)    ──┘
P0-3 (dump异常)    ──── 第二批：依赖 P0-2 的 catch 模式

P1-1 (类型提取)    ──┐
P1-2 (前向声明)    ──┤ 第三批：依赖 P1-1 的类型就位
P1-3 (json驱逐)    ──┤
P1-4 (冗余include) ──┘
P1-5 (CMake链接)   ──── 可随时插入

P2-1~P2-3 (大文件拆分) ── 第四批：依赖 P1 类型基础稳定
P2-4 (错误码)      ──┐
P2-5 (平台抽象)    ──┤ 第五批：可与 P2-1~3 并行
P2-6 (去重)        ──┘

P3-1~P3-5 (测试+性能) ── 第六批：依赖 P2 稳定后执行
```

## 七、验证方式

每阶段完成后执行：
```bash
# 编译验证（零警告）
cmake --build build -j6

# 全部测试通过（5 个现有 + 新增）
ctest --test-dir build --output-on-failure -j6

# 手动冒烟测试
./bin/Debug/CLFCode.exe
# 验证: 启动横幅 → 输入对话 → 工具调用 → ESC 中断 → /mode 切换 → /resume → /clear → /exit
```

验收标准：
- P0 后：零已知崩溃/UB/数据竞争
- P1 后：CLFAgentLoop.hpp 编译影响从 8 单元降到 ≤4；nlohmann/json 不出现在任何 .hpp
- P2 后：所有 .cpp ≤ 300 行；新增工具/命令/安全模式无需改已有类（OCP）
- P3 后：测试覆盖 CLFHttpClient/CLFCommandExec/CLFStreamAccumulator；关键性能热点消除
