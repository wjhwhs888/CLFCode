# 设计：渐进式工具显示 + 双计时器

> 状态：设计中 | 创建：2026-08-10 | 基于 todo.md | 借鉴 CLFTurnRunner 方案

## 〇、需求原文（todo.md 摘要）

| # | 需求 | 说明 |
|---|------|------|
| ① | 工具渐进显示 | 执行中只显示当前工具，前一个消失；每秒更新 |
| ② | 批次折叠 | 全部完成后折叠为一行 summary；ctrl+t 展开明细 |
| ③ | 文件修改不隐藏 | write_file / edit_file 始终走永久滚动区，展示 diff |
| ④ | 整体计时 | StatusLine 全程显示 `Working for 13s…`，turn 结束清空 |
| ⑤ | 末尾总结 | 永久内容追加 `✻ Cooked for 38s` |

## 一、双计时器设计（借鉴 CLFTurnRunner 方案）

### Timer #1：每动作计时（已有，增强）

| 阶段 | 显示位置 | 内容 |
|------|---------|------|
| API 等待中 | StatusLine | `· Thinking… (5s)`（已有，CLFThinkingIndicator） |
| 工具执行中 | 进度块 | `● thinking for Xs` + 当前工具（新增：showProgress） |
| 批次完成 | 永久内容 | `● thought for 9s，read 2 files (ctrl+t to expand)`（新增：finishProgress） |

### Timer #2：整体任务计时（新增）

| 阶段 | 显示位置 | 内容 |
|------|---------|------|
| turn 运行中 | StatusLine | `Working for 55s…`（每 200ms 刷新，覆盖 Timer #1） |
| turn 完成 | 永久内容 | `✻ Cooked for 1m55s`（RAII Guard 自动 emit） |

### 关键设计点

- Timer #2 与 Timer #1 刷新频率一致（1Hz），无冲突
- Timer #2 用 RAII Guard 保证任意退出路径都自动清理 + emit 总结
- `m_progressLines` 加 `std::mutex` 保护并发访问（思考线程 + 工具线程）
- 两个计时器都**不引入新 C++ 类**，仅在现有函数内加线程 + 变量

## 三、CLFAgentLoop 改造

### 3.1 思考计时 + 进度块更新

API 等待阶段与工具执行阶段是**串行**的（先等 API → 返回 tool calls → 执行工具 → 下一轮 API），不存在并发调用 showProgress。

- **API 等待期**：thinkingTimer 线程每秒调 `showProgress({"● thinking for Xs"})`
- **工具执行期**：ToolExecutor 调 `showProgress({thinkingLine, toolHeader, toolResult})`

thinkingTimer 在工具执行前停止，ToolExecutor 结束后下一轮 thinkingTimer 重新启动。两者不重叠。

```cpp
// CLFAgentLoop 流式路径 — RAII 确保异常时自动 join：
struct ThinkingGuard {
    std::atomic<bool>& active;
    std::thread& t;
    ~ThinkingGuard() { active.store(false); if (t.joinable()) t.join(); }
};

std::atomic<bool> thinkingActive{true};
std::thread thinkingTimer([&]() {
    int s = 0;
    while (thinkingActive.load()) {
        m_output->showProgress({"● " + m_labels.thinking + " for " + std::to_string(s) + "s"});
        sleep(1s); ++s;
    }
});
ThinkingGuard thinkingGuard{thinkingActive, thinkingTimer};
// ... API 调用（即使抛异常，ThinkingGuard 析构也会 join）...
```

### 3.2 整体计时（Timer #2）+ RAII 清理

```cpp
auto turnStart = now();
std::atomic<bool> timerOn{true};
std::thread timer([&]() {
    while (timerOn) {
        m_output->setStatus(m_labels.working + " for " + elapsed + "s…");
        sleep(1s);  // 与 CLFThinkingIndicator 一致，避免渲染压力
    }
});

// RAII Guard（任意退出路径均自动清理）
struct Guard {
    ~Guard() {
        timerOn = false;  timer.join();
        m_output->setStatus("");
        auto ts = formatDuration(now() - turnStart);
        m_output->emitContent("\n✻ " + m_labels.cooked + " for " + ts + "\n\n");
    }
} guard;
```

`formatDuration(seconds)` 提取为公共工具函数（`CLFTypes/CLFEncoding.hpp` 或新建 `CLFUtils.hpp`），避免在 AgentLoop 和 ToolExecutor 中重复实现。

### 3.3 标签可配置

新增轻量配置结构体，通过构造函数注入，避免硬编码：

```cpp
// CLFTypes/CLFTypes.hpp
struct CLFTimerLabels {
    std::string thinking = "thinking";   // Timer #1 进行中 → "● thinking for 3s"
    std::string thought   = "thought";    // Timer #1 完成   → "● thought for 3s，read 2 files"
    std::string working   = "Working";    // Timer #2 进行中 → "Working for 13s…"
    std::string cooked    = "Cooked";     // Timer #2 完成   → "✻ Cooked for 38s"
};

// CLFAgentLoop.hpp — 构造函数注入（默认 {}）
explicit CLFAgentLoop(const CLFAgentConfig& config,
                      std::shared_ptr<ICLFHttpClient> httpClient = nullptr,
                      const CLFTimerLabels& labels = {});
```

所有 `"thinking"` / `"thought"` / `"Working"` / `"Cooked"` 字符串均替换为 `m_labels.xxx`。
