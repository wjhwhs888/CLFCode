## 一、方向要点（占位，激活时细化）

### 1.1 事件 codec

- 同一 CLFEvents 头结构序列化（协议头即规范——用户定调 6）
- JSON 序列化规则：事件类型 → 字符串名（snake_case）；seq/turnId/callId 直传；载荷字段按类型裁剪
- 帧协议蓝本：dsh JSON-RPC 2.0（newline-delimited、stdout 纯协议通道、诊断走 stderr）——`设计/dsh/设计-dsh后端接入-实现方案.md` §1 复用资产

### 1.2 传输层

- 候选：WebSocket（HTML 本地/远程）/ stdio 帧协议（Qt 子进程模式）——形态按首个新 UI 定
- 请求-响应原语跨进程化：ConfirmRequested/ConfirmResponse 经传输层往返（requestId 关联；**有未决审批则连接不得关闭**——Claude Code control 协议教训）
- 心跳/重连：无人订阅缓冲不丢弃语义的跨进程扩展（总线默认记录队列 → 重连后补发）

### 1.3 新 UI 接入要点

- Qt：订阅者直接消费（同进程或经 codec 跨进程）——Qt 信号槽映射事件
- HTML：CLFCode 后端进程 + WebSocket 服务 + 前端订阅渲染；ask_user 类交互评估（分册本阶段定：ConfirmRequested 已覆盖确认场景；开放式提问需协议扩展，届时评估）
- 安全模式/确认语义跨进程保真（审批是安全关键点——confirm 超时默认拒绝语义随协议传播）
