## 一、背景与目标

core 与 UI 之间事件总线唯一通道的**最后一段双轨**：流式内容（ContentDelta）、推理增量（ReasoningDelta）、状态点（StatusChanged）、清推理（ThinkingCleared）在步骤 2 已双轨发射，但 core 直调（ICLFOutput）**仍保留**（防双份显示——适配器只记录不渲染）。本批：

1. **适配器启用全渲染映射**（renderToOutput=true 时渲染全部语义帧）
2. **core 移除内容渲染直调**（AgentLoop 10 处 + Executor 的 header/✓/✗/失败行）
3. **交互/反馈类直调有意保留**（diff 预览渲染、进度条、requestRefresh、onInterrupt 接线——跨进程协议阶段的独立议题）
4. **输出逐字对比验收**（分册 1 §3.5 定案——切轨验收 = 直调与事件渲染逐字一致）

**目标**：TUI 观感零变化；core 无内容渲染职责（数据与显示分离完成——为步骤 5 跨进程协议铺路）。

## 三、设计定案

### 3.1 切轨原则

- **内容渲染走事件、交互反馈留直调**——保留清单（onInterrupt/requestRefresh/renderDiff/showProgress/finishProgress）均为交互/瞬态反馈，跨进程协议阶段（步骤 5）再议
- 切轨同步：每处"移除直调"与"适配器渲染"同批完成（分册 1 R1 双份显示漏洞纪律）
- 逐字对比：切轨后适配器渲染输出与切轨前直调输出**逐字节一致**（qa 断言 + 实机对比）

### 3.2 决策点

1. **新事件 TurnError**（语义帧）：回合内错误/重试文案通道——覆盖 212/433/1003/1013 四类文案（✗ Exception retry / Stream error / 致命 HTTP / ⚠ retry）。payload：m_text（文案全文，core 拼好）。状态点仍走既有 StatusChanged。文案归 core 拼（含错误详情——协议传输完整文案，UI 直接显示）。
2. **工具显示行重建**：formatToolResult（结果 JSON → ok/text/lines/chars）**上提 CLFTypes/CLFTextUtil**（纯函数、公共层）——适配器与 core finalize **同函数**（单点维护，避免两处口径漂移）；✓/✗ 行文案模板在适配器（TUI 层文案归 TUI——分册 2 m_timerLabels 同款原则）。
3. **Write diff 预览事件化**（2026-10-14 用户拍板修正）：新增 `DiffPreview` 事件——其他 UI（Qt/HTML）的写文件确认依赖 diff 显示，不能留直调。payload：filePath + 行列表（text + style 数值）+ 统计（added/removed/hunks/truncated）。渲染行数受限（head/tail 32+2 截断后 ≤34 行）——单事件 payload 可控。**注意**：用户此前观察"直调保留是否出问题"——直调项均有 nullptr 守卫（无 TUI 安全跳过不崩溃），但功能缺失不可接受 → diff 事件化。renderDiff 输出顺序（含前导空行 emitContent("")）由适配器重建。
4. **进度条保留直调**：showProgress/finishProgress——用户拍板"单行覆盖先行"（设计 3 §六 验收 4），列表化待事件化 UI 稳后再议；步骤 5（跨进程协议）时加 Progress 事件（届时以新 UI 真实需求驱动设计）。
5. **转圈/中断回调/requestRefresh 保留**：TUI 特化形态（渲染帧刷新 + UI→core 中断通知）——新 UI 有等价机制（IPC 中断通知在步骤 5 设计）；均有 nullptr 守卫。
6. **协议补字段**（协议头即规范——加字段不破坏既有）：
   - `ToolStarted.m_showHeader`（bool）：prepare 的 header 行显示条件（非渐进 || Write）——core 算好，适配器照做
   - `ToolFinished.m_showResult`（bool）：finalize 的 ✓/✗ 行显示条件（!progressive || isWrite || !ok）
   - `ToolFinished.m_displayError`（string）：prepare 失败路径的 ✗ 行短文案（unknown/blocked/denied/预览失败 errorMsg/File too large/File modified）——errorKind 不足以区分 blocked/denied 的行文案（都是 permission）
   - `TurnFinished.m_emitText`（bool）：wrapUp 内容渲染条件（capReached && stream）——适配器无条件渲染会与流式双份

### 3.3 适配器渲染映射（renderToOutput=true）

| 事件 | 渲染 |
|---|---|
| ContentDelta | m_output->emitContent(text) |
| ReasoningDelta | m_output->appendThinking(text) |
| ThinkingCleared | m_output->clearThinking() |
| StatusChanged | m_output->setStatusKind((StatusKind)kind) |
| TurnError（新） | emitContent(m_text)（文案含 "\n✗/⚠" 前缀与换行，core 拼好直显） |
| ToolStarted | m_showHeader → emitContent("\n● name(param)\n")；渐进读工具 → showProgress 单行 |
| ToolFinished | m_showResult → ✓/✗ 行（formatToolResult 重算 + TUI 模板）；prepare 失败路径 → "  ⎿ ✗ " + m_displayError 行 |
| DiffPreview（新） | renderDiff 重建（行列表逐条 emitStyledLine + 尾随 emitContent("")） |
| TurnFinished | 现有 ✻/📋 + m_emitText → emitContent(m_text) |

### 3.4 中断行

prepare 的"  ⎿ ⏹ 已中断"行经核实为准死代码（fillPool 前置中断检查拦截——用户实机观察确认中断只显示一行）——移除直调，无观感变化，逐字验收无豁免。

### 3.5 事件协议变更清单

1. CLFEvents.hpp：枚举加 `TurnError`、`DiffPreview`（语义帧，22 → 24 事件）
2. payload 补字段：ToolStarted.m_showHeader（bool）+ m_warningText（string）/ ToolFinished.m_showResult（bool）+ m_displayError（string）/ TurnFinished.m_emitText（bool）——默认值保持既有 qa 断言
3. TurnError payload：m_text（文案全文）
4. DiffPreview payload：m_text（filePath）+ m_lines（vector<pair<string,int>>——text + style 数值）+ m_diffAdded/m_diffRemoved/m_diffHunks（int）+ m_diffTruncated（bool）

## 六、风险与开放项

- **qa 装配改动面**：qa_CLFAgentLoop 用例多（43 tests）——装配 helper 单点改造 + drainAll 时机（A5 先例）；逐字断言失败即切轨 bug（对照调试——事件 payload 与直调参数对齐表）

- **TurnError 与 StatusChanged 的配对**：错误场景两事件（文案 + 状态）——适配器渲染顺序 = 发射顺序（保序）✓

### 7.2 设计偏差（记录）

1. **m_showResult → m_displayResult**：✓/✗ 行由 core 拼**全文**（含前缀换行）而非适配器重算——formatToolResult 上提保留（core 拼行用）但适配器零重算；"TUI 文案归 TUI"原则的例外（工具显示行是 core 语义的显示表达——与 m_displayError 同构）。
2. **m_warningText 从 ToolStarted 移 ToolFinished**：⚠ 行需在 confirm 前显示，但 ToolStarted 发射时危险判定尚未发生——随 ToolFinished（渲染序 ⚠ → ✗ → ✓/✗ 由适配器固定）。
3. **ToolStarted 发射点后移**（查找后）：showHeader 条件（!progressive || Write）发射时可算——blocked 前 header 已显示的现状语义保持。
4. **中断行确认准死代码**：用户实机观察中断只显示一行 ✓——prepare 中断行移除无观感变化。

### 7.3 实抓缺陷

- **qa_CLFAgentLoop 全组 exit=3 + Debug 弹窗**（零输出）：`vector::front() called on empty`——out.kinds.front()（T 系列状态点断言）空——根因链：makeAgent/harnessFrom **漏 setEventBus** → 事件零发射 → 适配器零渲染 → kinds 空 → 断言失败后 front() 弹窗。定位手段：_CrtSetReportMode 重定向断言到 stderr（临时注入用完删）。修复：两处装配点补 setEventBus → 43 tests / 40145 asserts 全绿。
