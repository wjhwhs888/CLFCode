# 设计-工具调用闭环

## 设计目标

将 `CLFTools` 模块的真实工具（文件读写、命令执行）注册到 Agent，使模型能通过 tool_calling 机制实际操作系统资源。

## 当前现状

核心循环（`runTurn`）和上下文（`CLFMessage`/`CLFContext`）已在 API 协议适配阶段实现：
- ✅ 多轮 tool-calling 循环
- ✅ tool_call_id 回传机制
- ✅ finish_reason 中止条件
- ✅ 工具异常回传 LLM
- ✅ 最大轮次限制（16 轮）
- ❌ 真实工具未注册（仅测试用 echo / get_current_time）

## 实现方案

### 1. 工具 Handler 适配

CLFTools 现有函数签名与 CLFTool handler 不一致：

| 工具 | 现有签名 | CLFTool handler 要求 |
|------|---------|---------------------|
| `readFile` | `(path) → CLFFileResult` | `(jsonArgs) → string` |
| `writeFile` | `(path, content) → CLFFileResult` | `(jsonArgs) → string` |
| `listDirectory` | `(path) → CLFFileResult` | `(jsonArgs) → string` |
| `executeCommand` | `(command, timeout) → CLFCommandResult` | `(jsonArgs) → string` |

**方案**：在 `main.cpp` 中写 4 个适配函数（lambda），内部解析 JSON → 调用工具 → 序列化结果为 JSON 字符串返回。

不新建类——工具注册是 main.cpp 的职责（依赖注入），CLFTools 模块保持独立。

### 2. 参数 Schema 定义

HTTP API 传输
```

readFile:
  path: string (required)

writeFile:
  path: string (required)
  content: string (required)

listDirectory:
  path: string (required)

executeCommand:
  command: string (required)
  timeout: int (optional, default 30)
```

### 3. 返回格式

统一用 JSON 字符串返回，方便模型理解结果：

成功：`{"success": true, "content": "..."}`
失败：`{"success": false, "error": "..."}`

命令执行额外带 exitCode。

### 4. 文件变更

| 文件 | 变更 |
|------|------|
| `src/main.cpp` | 新增 4 个工具适配函数 + 工具注册 |
| `.claude/plans/设计/设计-工具调用闭环.md` | 本文件 |

### 5. 安全考虑

写文件和命令执行属于高风险操作，但安全策略（`分析-安全策略.md`）暂未实现。当前阶段：工具可用但无权限控制，实施安全策略时再加拦截层——`CLFTool` 的 handler 本身不需感知安全策略。
