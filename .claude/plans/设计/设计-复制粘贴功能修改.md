## 二、粘贴：CLFPasteCoalescer

### 2.1 状态机

```
IDLE ──Return──→ PENDING_SUBMIT（捕获文本，开 40ms 静默窗，输入框不清空）
IDLE ──Return(空文本)──→ 同样进 PENDING（实现定稿：粘贴以空行开头 "\nfoo" 的首个
    Return 即空文本，短路会丢前导空行；窗满后提交分支对空文本 no-op，现状空回车语义不变）
PENDING_SUBMIT ──窗内 Character──→ PASTE_MODE（恢复文本 + '\n' + 字符）
PENDING_SUBMIT ──窗内 Return──→ PASTE_MODE（恢复文本 + '\n' + '\n'；见空行规则）
PENDING_SUBMIT ──任何非 Character/Return 事件──→ 取消 → IDLE（文本保留；**终审补入**：
    ArrowUp 历史导航等会直接替换 inputText——不取消则窗满提交错文本）
PENDING_SUBMIT ──窗满无事件──→ 确认（timer 置标志 + wakeCb）→ 主循环复位状态并提交 → IDLE
PASTE_MODE ──Return(距上事件≤40ms)──→ 插 '\n'（复用 Ctrl+N 机制 input->OnEvent(Character("\n"))）
PASTE_MODE ──Character(距上事件≤40ms)──→ PassThrough（字符进输入框，保持 PASTE_MODE，更新 m_lastPasteEvent）
PASTE_MODE ──Return(距上事件>40ms)──→ 退出 PASTE_MODE，按 IDLE 的 Return 重新处理（提交）
PASTE_MODE ──任何非 Character/Return 事件──→ 退出 PASTE_MODE，正常处理该事件（终审补入：
    非粘贴事件天然结束粘贴序列，与时间窗无关——方向键/快捷键即按即生效）
```

- **空行规则（外部审查补入）**：粘贴含空行时（如 `a\n\nb`），PENDING_SUBMIT 内到达的下一个事件是 **Return 而非 Character**。此时转 PASTE_MODE 并恢复 `pendingText + "\n" + "\n"`——第一个 `\n` 是待提交那次 Return 的换行，第二个 `\n` 是本次 Return（空行）的换行。若此转移缺失会错误提交 `a`。连续空行同理（每个 Return 补一个 `\n`）
- **PENDING 期内 inputText 不变式（终审补入）**：窗口期内 inputText 仅由 Character/Return 路径改写（两者都先取消待提交）；任何其他事件一律取消待提交后才处理——保证窗满确认时 `inputText == pendingText`，提交无需文本回拷
- **时间来源（外部审查补入）**：FTXUI `Event` 结构体**无 timestamp 字段**（event.hpp 核实，仅 type_/input_）→ 合并器在 CatchEvent 处理事件时记录 `steady_clock::now()`；同一 ReadConsoleInput 批次的事件被连续处理，处理时差 ≈ 到达时差（前提：Return 分支不阻塞——`asyncSubmit.launch` 异步 ✓ 既有路径已满足）；时钟注入单测
- 阈值常量 `kPasteQuietWindowMs = 40`（保守值；同一 ReadConsoleInput 批次事件间隔 μs 级，人手键入 >100ms，安全边际充足）
- 单行粘贴带尾 `\n`：窗满无后续 → 正常提交，与手打回车等价（符合直觉）
- 多行粘贴：窗内后续字符必达 → 全部并入输入框，Enter 一次提交
- **不读剪贴板、不依赖终端协议、不 patch 3rdparty，Ctrl+V 与 Shift+右键两条通道天然覆盖**（两者走同一事件路径）
- **超大粘贴分批到达（外部审查补入，已知边界）**：控制台将超大文本分多批写入时，批间隔可能 >40ms → PASTE_MODE 提前退出。自愈机制：退出后走 IDLE→PENDING，下一批事件（字符或 Return）落入 40ms 窗内 → 文本无损重回 PASTE_MODE；真失败条件仅"批间隔 >40ms 且该批以 Return 结尾后不再有后续事件"（表现为整段自动提交，非丢文本）。验收时实测 ~10KB 大文本粘贴批间隔（清单第 10 条），>40ms 则记入已知问题后续项（如 PASTE_MODE 独立宽阈值）

### 2.2 类接口

```cpp
namespace CLF::CLFUI {

class CLFPasteCoalescer {
public:
    // wakeCb：定时线程唤醒主循环的通道（CLFRepl 注入
    //   [&]{ screen.PostEvent(ftxui::Event::Custom); }）——类内无 screen 引用（终审补入）
    // quietWindowMs：静默窗时长，默认 40，测试注入 5ms 加速（终审补入）
    explicit CLFPasteCoalescer(std::function<void()> wakeCb, int quietWindowMs = 40);
    ~CLFPasteCoalescer();  // 常驻定时线程 join（终审补入：常驻 cv 线程，
                           // 避免 per-Return 短命线程的 join 管理/detach 风险）

    // 事件入口（CLFRepl CatchEvent 调用）。now 注入以便单测。
    // 返回对当前事件的处理指令；文本拼接动作由 CLFRepl 执行——
    // 事件字符在 CLFRepl 手中（e.character()），pendingText 经 pendingText() 查询。
    enum class Action {
        PassThrough,             // 放行给 Input（PASTE_MODE 内字符 / IDLE 任意事件）
        Consume,                 // 吃掉，无文本动作（取消待提交 / 空文本 Return 短路）
        RestoreAndAppendChar,    // PENDING→PASTE（字符触发）：CLFRepl 执行
                                 //   inputText = pendingText() + "\n" + e.character()
        RestoreAndAppendNewline, // PENDING→PASTE（空行 Return 触发）：CLFRepl 执行
                                 //   inputText = pendingText() + "\n\n"
        InsertNewline,           // PASTE_MODE 内 Return：CLFRepl 执行
                                 //   input->OnEvent(Event::Character("\n"))
    };
    // inputText 为捕获源（捕获通道，外部审查补入）：进入 PENDING_SUBMIT 时存入 m_pendingText
    Action onReturn(TimePoint now, const std::string& inputText);
    Action onCharacter(TimePoint now);        // 字符事件（含粘贴突发字符）
    Action onOtherEvent(TimePoint now);       // 任何其他事件：PENDING→取消待提交；
                                              // PASTE_MODE→退出；IDLE→PassThrough（终审补入）

    // 窗满确认状态（主循环在 CatchEvent 顶部轮询，线程安全）
    bool pendingConfirmed() const;
    // 仅主循环调用！幂等（终审补入）：仍处 PENDING_SUBMIT 才复位回 IDLE 并返回 true
    // （= 应执行提交）；状态已变（竞态被取消）→ 仅清标志返回 false。
    // 提交动作由调用方用当前 inputText 走既有 :414 提交分支执行——
    // 窗口期内 inputText 未被改写（不变式见 2.1），无需文本回拷。
    // confirm 激活或 asyncSubmit.busy() 时调用方只复位不提交（文本留在输入框）。
    bool consumePendingConfirmation();

    // 供 CLFRepl 查询/接管文本
    const std::string& pendingText() const;

private:
    enum class State { Idle, PendingSubmit, PasteMode };
    State       m_state = State::Idle;
    std::string m_pendingText;
    TimePoint   m_lastPasteEvent;
    TimePoint   m_deadline;        // 定时线程唤醒时刻
    std::mutex  m_mutex;           // 保护 m_state/m_pendingText/m_deadline/m_pendingActive
    std::condition_variable m_cv;
    bool        m_pendingActive = false;   // cv 谓词
    std::thread m_timer;                   // 常驻线程：wait_until(deadline, !pendingActive)
                                           // 到点仍 active → 置 m_pendingConfirmed + wakeCb()
    std::function<void()> m_wakeCb;
    std::atomic<bool> m_pendingConfirmed{false};
};
}
```

**主循环消费路径**（CLFRepl CatchEvent 顶部，任何事件到达时）：
```cpp
if (m_pasteCoalescer.pendingConfirmed()) {
    bool shouldSubmit = m_pasteCoalescer.consumePendingConfirmation();
    if (shouldSubmit && !terminal->isConfirmActive() && !asyncSubmit.busy())
        executeSubmitBranch(inputText);  // 与 :414 提交分支同一段代码
    // shouldSubmit=false（竞态已取消）或 confirm/busy：文本留在输入框，不提交
}
```

**关键时序**（消除竞态）：
- Return → 主循环调用 `onReturn(now, inputText)`：捕获文本、状态 PendingSubmit、cv 通知定时线程（deadline=now+40ms）、输入框**暂不清空**（用户仍可见自己的文本）
- 窗内 Character → `onCharacter` 返回 `RestoreAndAppendChar`：合并器取消定时（cv 唤醒定时线程继续 wait）、进 PASTE_MODE；**CLFRepl 执行** `inputText = pendingText() + "\n" + e.character()`
- 窗满 → 定时线程置 `m_pendingConfirmed` + `wakeCb()`（PostEvent Custom）→ 主循环在 CatchEvent 顶部消费（`consumePendingConfirmation`，提交由既有 :414 分支代码执行）
- 任何其他事件（Esc/中断/confirm 激活/方向键/Ctrl 快捷键）→ `onOtherEvent`：取消待提交/退出 PASTE_MODE，随后按正常流程处理该事件，文本保留在输入框

**边界**：
- 粘贴发生在 confirm 激活期：confirm 分支先消费一切事件（既有行为），合并器收不到事件 → 粘贴文本被吞，与现状一致
- confirm 激活瞬间若有 PendingSubmit：`onOtherEvent` 取消（并入 confirm 激活处调用）
- PendingSubmit 期间 Ctrl+C 退出程序：`onOtherEvent` 取消，文本不提交

## 三、复制：CLFSelectionModel + 行映射表

### 3.1 行映射表 RowMap

渲染器建 `allLines` 的同一趟循环里，并行生成（CLFRepl.cpp 渲染 lambda 内）：

```cpp
enum class RowKind {
    Content,      // snapshot.lines[lineIdx] 的第 partIdx 个硬换行 part
    Pending,      // snapshot.pendingLine（按字节 wrap）
    ThinkingFold, // 思考折叠摘要行
    ThinkingLine, // 思考展开行 [lineIdx]
    FoldSummary,  // 恢复回显折叠摘要行
    FoldLine,     // 恢复回显折叠展开行 [lineIdx]
    Progress,     // progressLines[lineIdx]
    Status,       // 状态行
    ScrollHint,   // 滚动提示行（不可选）
};
struct RowInfo {
    RowKind kind;
    size_t  lineIdx   = 0;   // 源数组下标
    size_t  partIdx   = 0;   // 硬换行 part 序号
};
```

> **实现定稿简化（M2 落地）**：`byteStart/byteEnd` 字段取消——选区坐标与提取均以**渲染行文本 rowTexts**（WYSIWYG，含前缀与动画帧）为源，提取直接截取渲染文本逐行拼接，无需按 RowKind 解析源串（原"源字符串定义"表由 rowTexts 替代）。选区覆盖范围为**滚动区内容行**（Progress/Status 枚举保留但渲染器不产出——progress/status 行位于滚动区外，一期不做）。

- 构建规则与现有渲染**逐行镜像**：`allLines.push_back` 的每一处都伴随 `rowMap.push_back`；硬换行 vbox 的每个 part 各占一个 RowInfo（byteStart/byteEnd 为 part 对应的子串区间）
- **源字符串定义（终审补入）**——byteStart/byteEnd 参照的源串按 kind 明确，提取与列→字节换算共用：

| RowKind | 源字符串 |
|---------|---------|
| Content | `snap.lines[lineIdx]`（part 对应硬换行切出的子串区间） |
| Pending | `snap.pendingLine`（按字节 wrap 的子串区间，与现有渲染一致） |
| ThinkingFold | 折叠摘要整串（"  Thought for Ns · …(ctrl+t 展开)"） |
| ThinkingLine | `"  " + thinkingLines[lineIdx]`（含缩进前缀——所见即所得） |
| FoldSummary | 折叠摘要整串（含 "  ▸/▾ " 前缀） |
| FoldLine | `"  " + foldedLines[lineIdx]`（含前缀，part 对应硬换行子串） |
| Progress | `progressLines[lineIdx]`（末行含动画帧，取当前帧渲染串） |
| Status | 当前渲染状态行整串（含 "  ●" 前缀与动画帧） |
| ScrollHint | 不可选 |

- ScrollHint 行不可选（点击 clamp 到最近内容行）
- 选区覆盖范围 = 全部显示内容（与"所见"一致）
- **已知边界（终审补入）**：① 流式更新期间，尾部易变行（pendingLine/thinking/progress/status）随帧变化，对它们的选区可能漂移——提取基于复制时刻最新快照，静态 Content 区行索引不受 append 影响，稳定；② 超宽未硬换行行（思考展开行等，现有渲染即不硬换行）按整行映射，超出终端宽度部分不可见但可被选区包含——与渲染现状一致，不为此扩硬换行范围

### 3.2 坐标映射

- 可见窗口：`CLFScrollView` 新增 `visibleRange() → [startLine, endLine)`（把 renderWindow 内部切片逻辑上提为 update() 计算并存储）
- **口径定义（外部审查补入）**：`visibleRange()` 返回的是**内容渲染行区间（不含提示行）**；提示行偏移由独立的 `topHintCount()`（0/1）单独提供——两个值口径分开，不混算
- 鼠标 `(x, y)` → 渲染行：`globalRow = startLine + y - topHintCount`（**坐标基准 0 基——验收实测修正**：本环境 WT/ConPTY 实际投递 0 基，FTXUI 自身 Input 点击定位亦按 0 基 Box 对比原始坐标（input.cpp HandleMouse）；按 SGR 规范做 `-1` 反而整体偏上一行；提示行偏移单独由 topHintCount 扣除；S1 单测兜底验证）
- 列 x → 字节偏移：对该行源文本做 displayWidth 逆向走查（CJK 感知，复用渲染器现有 charWidth 逻辑，提取为公共 helper 避免三处重复——渲染硬换行、选区换算、高亮拆分共用）
- 出界 clamp：行超出窗口 → 忽略；列超出行尾 → 行尾

### 3.3 选区状态机（CLFSelectionModel，纯逻辑）

```cpp
class CLFSelectionModel {
public:
    // 进入/退出
    void startAt(int row, int byteOff);   // 鼠标按下 / Ctrl+S 进入
    void extendTo(int row, int byteOff);  // 拖拽 Moved / 方向键
    void moveCursor(enum Dir { Up, Down, Left, Right, Home, End });  // 键盘移动
    void clear();
    bool active() const;

    // 归一化区间 [row, byteOff) → (row, byteOff)，反向选区自动交换
    struct Range { int fromRow, fromByte, toRow, toByte; };
    Range range() const;

    // 与渲染的接口：给定 row 的 RowInfo 与源文本，返回该行选区字节区间（无选区返回 nullopt）
    std::optional<std::pair<size_t,size_t>> rowSelection(size_t globalRow, const RowInfo&) const;

    // 提取：给定 rowMap + ContentSnapshot → 剪贴板文本（纯函数）
    static std::string extract(const Range&, const std::vector<RowInfo>& rowMap,
                               const CLFTerminal::ContentSnapshot& snap);
private:
    int m_anchorRow=-1, m_anchorByte=0, m_cursorRow=-1, m_cursorByte=0;
    bool m_active=false;
};
```

**提取规则（换行正确性的核心）**：
- 按渲染行序遍历选区覆盖的 RowInfo，取 `[max(fromByte, byteStart), min(toByte, byteEnd))` 子串
- **同一逻辑行的多个 part 直接拼接不加 `\n`**（硬换行点不产生假换行）；跨逻辑行才加 `\n`（判断：相邻两个 RowInfo 的 `kind+lineIdx` 不同）
- ScrollHint 行跳过；空选区返回空串
- 结果送 `CLFClipboard::write`（F1 复用）

### 3.4 交互设计

| 操作 | 行为 |
|------|------|
| 左键按下 | 进入选区，锚点=按下点 |

| Esc | 取消选区（不动剪贴板） |
| confirm 激活 | 立即 clear 选区（与粘贴合并器同步处理） |
| 选区态中其他按键 | 消费，不落输入框 |
| 输入框区域鼠标事件 | 放行给 Input（选区覆盖不含输入框——RowMap 仅内容显示区行；既有点击定位光标行为不变） |

**选区模态（外部审查补入）**：选区激活 = 输入框事件隔离——CatchEvent 全量消费方向键/字符等事件，输入框不接收任何输入；选区结束（复制/Esc）后恢复。**不做 TakeFocus 切换**：项目已禁用 TakeFocus（DSR/CPR 泄漏风险，`CLFRepl.cpp:86` 注释），且输入框焦点样式已被 `inputOpt.transform` 去除——视觉上无焦点差异，模态纯靠事件路由实现。

### 3.5 高亮渲染

- 渲染器对每个可见行查 `rowSelection()`：无选区 → 原样；有选区 → 拆三段 `hbox(前 | 选中(bgcolor) | 后)`，选中段用 `ftxui::bgcolor(ftxui::Color::Grey30)`（本版 FTXUI 无 BlueGrey，实现定稿）
- **"行"= 渲染行（part），非逻辑行（外部审查补入）**：可见行是硬换行后的 part，`rowSelection()` 返回的正是该 part 文本内的选区字节子区间；拆三段基于 **part 文本**与其字节区间进行，不得对逻辑行整行误拆
- 拆分按显示宽度列区间换算字节（共用 3.2 的公共 helper），不截断 UTF-8
- 已有颜色样式（diff 绿/红、dim）保留在整行元素上，bgcolor 只加选中段
