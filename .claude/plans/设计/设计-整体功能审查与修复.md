## 二、发现的问题（按优先级排列）

### 🔴 P0 — 功能性缺失（影响基本使用）

#### P0-1. 无 CLI 参数，无 `--help` / `--version`

`main.cpp:20` — `argc/argv` 被标记为 `[[maybe_unused]]`，完全不解析命令行参数。

**后果**：
- 无法通过 `CLFCode --version` 查版本
- 无法通过 `CLFCode --help` 了解用法
- 无法指定配置路径、项目根目录

**建议**：引入轻量参数解析（手写，不需要第三方库），支持：

| 参数 | 说明 |
|------|------|
| `--help`, `-h` | 显示帮助 |
| `--version`, `-v` | 显示版本号 |
| `--config <path>` | 指定配置文件 |
| `--project-root <path>` | 指定项目根目录 |
| `--prompt "<text>"` | 单次提问模式（非交互，输出结果后退出） |

#### P0-2. 无 `search_content` 工具

7 个工具中缺少文件内容搜索。模型只能通过 `execute_command("findstr ...")` 凑合。

**后果**：Windows/Mac/Linux 搜索语法不同，模型容易写出跨平台不兼容的命令。

**建议**：新增 `search_content` 工具：
- 参数：`pattern`（正则）、`directory`（搜索目录）、`glob`（文件过滤，可选）
- 对标 Claude Code 的 Grep 工具，内部用 C++ 递归目录 + 逐行匹配
- 风险等级：Read（不需要确认）

#### P0-3. 非交互模式缺失

当前只能交互式 REPL，无法用于脚本/CI。

**建议**：`--prompt` 参数触发非交互模式：
1. System prompt 构建（同交互模式）
2. 发送用户 prompt
3. 工具调用循环（安全策略用 `auto`）
4. 输出最终结果到 stdout
5. 退出

### 🟠 P1 — 用户体验缺陷（影响日常使用）

#### P1-1. `/model` 只显示不切换

`/model` 命令只输出当前模型名，不能运行时切换。

**建议**：`/model <name>` 切换主模型，`/model`（无参数）显示当前。

#### P1-2. write_file / edit_file 无备份机制

覆盖写入或精确替换后无法撤销。模型改错代码时用户只能靠 git。

**建议**：
- `edit_file` 修改前将原文件复制为 `.bak`（同名 + `.bak` 后缀）
- 或者依赖用户自己用 git（当前已有 `diff` 预览，问题不严重）

#### P1-3. 无累计 token 统计

`/context` 显示当前窗口用量，但没有本次会话累计消耗。

**建议**：在 `CLFAgentLoop` 中维护 `m_totalTokensUsed`，每次 API 响应后累加。`/context` 显示"本次会话累计: X tokens"。

#### P1-4. Ctrl+C 无优雅保存

进程被 `Ctrl+C` 强行终止时，最后一个 turn 可能丢失（`latest.json` 不是逐 turn 保存吗？不，检查 `CLFAgentLoop::runTurn`）。

**当前状态**：`latest.json` 的保存时机需要确认。如果是仅在 `/exit` 和 `/clear` 时保存，Ctrl+C 确实会丢数据。

**建议**：确认 `latest.json` 是否每个 turn 都在保存。如果已在保存，这个不是问题。

#### P1-5. 长会话无自动摘要

摘要只在 `/exit` 时生成。如果会话持续很久但从不退出，上下文会膨胀直到截断。

**建议**：`CLFAgentLoop::runTurn` 中，每次 turn 结束后检查窗口使用率，超过 70% 时自动触发摘要压缩。

### 🟡 P2 — 健壮性 / 安全（影响稳定性和安全性）

#### P2-1. `read_file` 无路径安全检查

可以读取任意路径文件（包括系统敏感文件如 `/etc/passwd` 或 Windows 注册表）。安全策略对读操作全放行。

**建议**：
- 添加工作区边界检查（默认不允许读取工作区外的文件，除非用户确认）
- 或者添加文件大小上限（避免读 10GB 文件撑爆内存）

#### P2-2. `execute_command` 无命令白名单/黑名单

任何命令都可以执行。虽然安全策略 `analyze` 模式阻断命令，但 `auto` 模式下完全放行。

**建议**：
- 添加危险命令模式匹配（`rm -rf /`、`format` 等）
- 工具 handler 内检查命令字符串，匹配危险模式时强制要求确认（不受安全模式影响）

#### P2-3. 配置文件无 schema 校验

`agent_settings.json` 加载时对字段做基本解析，但不会校验值范围（如 `temperature: 999` 会被接受，虽然 API 会报错）。

**建议**：`CLFConfigLoader` 中加范围检查 + 非法值时使用默认值 + 日志警告。

#### P2-4. Session 文件无版本号

会话文件（`.json`）没有格式版本标记。如果未来消息格式变化，旧文件无法正确解析。

**建议**：序列化时写入 `"format_version": 1`，加载时检查并做兼容处理。

#### P2-5. `write_file` schema 缺失 `force` 参数

`CLFToolExecutor` 的安全确认逻辑引用了 `force=true` 属性（"Use Auto mode or set force=true"），但 `CLFBuiltinTools.cpp` 中 `write_file` 的 JSON Schema 没有定义这个参数。模型无法传。

**建议**：在 schema 中补充 `"force": {"type": "boolean", "description": "..."}`。

#### P2-6. CLFHttpClient `m_wasAborted` 从未被设为 `true`

`ICLFHttpClient.hpp` 定义了 `m_wasAborted` 字段，`CLFAgentLoop` 检查它，但 `CLFHttpClient` 的 `abort()` 只调用 `client.stop()`，从不设置 `m_wasAborted = true`。中断检测在流式路径上依赖回调返回 false，在同步路径上完全失效。

**建议**：`abort()` 末尾设置 `m_wasAborted = true`。

#### P2-7. CLFRetryPolicy 对不可恢复的 HTTP 错误也重试

`isFatalHttpError` 只标记 400/401/402/403。404/405/409/413/422 等"请求本身有错"的状态码也会被重试 3 次，纯浪费时间。

**建议**：增加 `isRetriableHttpError` 正向匹配（429、5xx、超时），其余非 fatal 的错误最多重试 1 次。

#### P2-8. `get_current_time` 仅 Windows 可用

用了 `localtime_s`（MSVC 特有），无 POSIX 分支。Linux/macOS 上永远返回 `"[Error] Failed to get local time"`。

**建议**：`#ifdef _WIN32` 用 `localtime_s`，`#else` 用 `localtime_r`。

#### P2-9. `execute_command` 非零退出码一律视为失败

`exitCode != 0` → `success: false`。但 `grep`（无匹配返回 1）、`diff`（有差异返回 1）等大量命令用非零退出码传递有用信息。模型收到 `success: false` 会误判。

**建议**：成功的判定改为检查是否有 stdout 输出，退出码仅作为辅助信息。

#### P2-10. CLFConfigLoader 头文件注释 JSON 结构错误

`CLFConfigLoader.hpp` 22-36 行的注释示例使用 `"api"` 键名，但实际代码读取的是 `"connection"` 和 `"chat_completions"`。照注释写配置会不生效。

**建议**：修正头文件注释。

#### P2-11. `findProjectRoot` 使用 ANSI API

Windows 路径调用 `GetModuleFileNameA`，非 ASCII 路径字符会丢失。

**建议**：改为 `GetModuleFileNameW` + `WideCharToMultiByte` 转 UTF-8。

### 🟢 P3 — 功能增强（锦上添花）

#### P3-1. 无 web_fetch / web_search 工具

没有联网搜索能力，模型只能凭训练数据回答。

**建议**：后续引入 `web_fetch` 工具（HTTP GET → Markdown），可选 `web_search`（调用搜索 API）。

#### P3-2. 不支持多会话

一次只能有一个活跃会话，不能在不同项目/上下文之间切换。

**建议**：`/session list` + `/session switch <n>`。先不急，属于高级功能。

#### P3-3. 无配置文件热重载

改 `agent_settings.json` 后必须重启 CLFCode 才生效。

**建议**：`/reload` 命令重新加载配置。

#### P3-4. `edit_file` 空 `old_string` 导致死循环

`content.find("")` 返回 0，唯一性检查遍历所有位置匹配 `content.size() + 1` 次才报错。

**建议**：`old_string.empty()` 提前返回明确错误。

#### P3-5. 无操作系统信号处理器

`SIGINT`/`SIGTERM`/`SetConsoleCtrlHandler` 均未注册。进程被 kill 时无法保存会话。

**建议**：注册信号处理器，收到终止信号时尝试保存 `latest.json` 后再退出。

#### P3-6. Session 文件无并发锁

两个 CLFCode 实例在同一项目目录时会竞争 `latest.json`。无文件锁保护。

**建议**：写入前创建 `.lock` 文件，失败则提示用户。

#### P3-7. `findProjectRoot` 无深度限制

在没有 CMakeLists.txt 的目录中会遍历到文件系统根目录，可能跨越慢速网络挂载。

**建议**：限制最大向上遍历深度（如 20 层）。

## 三、实施路线

按优先级分 3 批：

| 批次 | 内容 | 预计发布 |
|------|------|:---:|
| **第一批** (P0) | CLI 参数（--help --version --prompt）+ search_content 工具 + 非交互模式 | v0.2.0 |
| **第二批** (P1) | /model 切换 + token 统计 + 长会话自动摘要 + 确认 Ctrl+C 已有保护 | v0.2.1 |
| **第三批** (P2-P3) | 路径安全 + 命令危险检测 + 配置校验 + session 版本号 | v0.2.x |

### 第一批详细步骤（建议先做）

#### Step 1：CLI 参数解析

**新增文件**：`src/CLFCore/CLFArgParser.hpp/.cpp`

命名空间中解析 `argc/argv`，返回结构化结果：

```cpp
struct CLFLaunchArgs {
    bool showHelp    = false;
    bool showVersion = false;
    std::string configPath;      // --config
    std::string projectRoot;     // --project-root
    std::string oneShotPrompt;   // --prompt（非空 = 非交互模式）
};
```

**修改**：`main.cpp` 先解析参数，再根据结果走不同分支。

#### Step 2：非交互模式

`--prompt` 触发时：
1. 初始化同交互模式（加载配置、日志、Builder）
2. 安全策略设为 `auto`
3. 调用 `agent.runTurn(prompt)`
4. 输出结果 + 退出

#### Step 3：search_content 工具

**新增文件**：`src/CLFTools/CLFSearchContent.cpp`

```cpp
// handler 实现:
// 1. 递归遍历 directory（depth-first，设置最大深度 20）
// 2. 如果有 glob 参数，先过滤文件名
// 3. 对每个文件逐行匹配 pattern（正则或纯文本）
// 4. 限制最大结果行数 500，超出截断标记
// 5. 返回格式: file:line: content
```

**注册**：加入 `CLFBuiltinTools::registerBuiltinTools()`，风险等级 Read。
