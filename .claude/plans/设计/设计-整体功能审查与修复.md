## 二、发现的问题（按优先级排列）

### 🔴 P0 — 功能性缺失（影响基本使用）

#### P0-1. 无 CLI 参数，无 `--help` / `--version`

`main.cpp:20` — `argc/argv` 被标记为 `[[maybe_unused]]`，完全不解析命令行参数。

**后果**：
- 无法通过 `CLFCode --version` 查版本
- 无法通过 `CLFCode --help` 了解用法
- 无法指定配置路径、项目根目录

**建议**：引入轻量参数解析（手写，不需要第三方库），支持：

| 参数 | 说明 |
|------|------|
| `--help`, `-h` | 显示帮助 |
| `--version`, `-v` | 显示版本号 |
| `--config <path>` | 指定配置文件 |
| `--project-root <path>` | 指定项目根目录 |
| `--prompt "<text>"` | 单次提问模式（非交互，输出结果后退出） |
| `--prompt-file <path>` | 从文件读取 prompt（支持多行，CI 友好） |
| `--allow-write` | 非交互模式下允许写/命令操作（默认仅 Read） |

#### P0-2. 无 `search_content` 工具

7 个工具中缺少文件内容搜索。模型只能通过 `execute_command("findstr ...")` 凑合。

**后果**：Windows/Mac/Linux 搜索语法不同，模型容易写出跨平台不兼容的命令。

**建议**：新增 `search_content` 工具：
- 参数：`pattern`（纯文本匹配）、`directory`（搜索目录）、`fileTypes`（扩展名过滤，如 `".cpp,.h"`，可选）
- `fileTypes` 用 `path.extension()` 比较，仅支持逗号分隔的扩展名列表。**不实现 glob 匹配**（`std::filesystem` 不提供，完整 glob 解析器过于复杂）
- 对标 Claude Code 的 Grep 工具，内部用 C++ 递归目录 + `std::string::find` 逐行匹配（不用正则，避免 `std::regex` 性能问题）
- 风险等级：Read（不需要确认）
- **默认跳过目录**：`.git/`、`node_modules/`、`__pycache__/`、`build/`、`dist/`、`.cache/`、`vendor/`（硬编码列表，后续可配置）
- **单文件大小上限**：1MB，超出跳过并备注
- **结果行数上限**：500 行，超出截断标记
- **搜索深度上限**：20 层

#### P0-3. 非交互模式缺失

当前只能交互式 REPL，无法用于脚本/CI。

**建议**：`--prompt` 或 `--prompt-file` 参数触发非交互模式：
1. System prompt 构建（同交互模式）
2. 发送用户 prompt
3. 工具调用循环（**安全策略强制 `block`**——只允许 Read 工具，Write/Execute 一律拒绝）
4. 如果用户传了 `--allow-write`，策略提升为 `auto`（用户显式授权，CI 脚本可审计）
5. 输出最终结果到 stdout
6. 退出

### 🟠 P1 — 用户体验缺陷（影响日常使用）

#### P1-1. `/model` 只显示不切换

`/model` 命令只输出当前模型名，不能运行时切换。

**建议**：`/model <name>` 切换主模型，`/model`（无参数）显示当前。

#### P1-2. write_file / edit_file 无备份机制

覆盖写入或精确替换后无法撤销。模型改错代码时用户只能靠 git。

**建议**：
- `edit_file` 修改前将原文件复制为 `.bak`（同名 + `.bak` 后缀）
- 或者依赖用户自己用 git（当前已有 `diff` 预览，问题不严重）

#### P1-3. 无累计 token 统计

`/context` 显示当前窗口用量，但没有本次会话累计消耗。

**建议**：在 `CLFAgentLoop` 中维护 `m_totalTokensUsed`，每次 API 响应后累加。`/context` 显示"本次会话累计: X tokens"。

#### P1-4. Ctrl+C 无优雅保存

进程被 `Ctrl+C` 强行终止时，最后一个 turn 可能丢失（`latest.json` 不是逐 turn 保存吗？不，检查 `CLFAgentLoop::runTurn`）。

**当前状态**：`latest.json` 的保存时机需要确认（实施 P1 前必须先读 `CLFAgentLoop::runTurn` 源码确认）。

**如果每个 turn 未保存**：升级为 **P0**（数据丢失风险），在第一批中修复每个 turn 后调用 `saveSession`。

**如果每个 turn 已保存**：降级为已解决，从清单移除。

#### P1-5. 长会话无自动摘要

摘要只在 `/exit` 时生成。如果会话持续很久但从不退出，上下文会膨胀直到截断。

**建议**：改用绝对值触发：`m_maxContextWindow - m_currentTokens < 4000` 时触发摘要（保留 4K token 余量）。阈值通过 `agent_settings.json` 的 `auto_summary_threshold` 字段可配置（默认 4000）。百分比阈值（如 70%）在不同窗口大小（16K vs 1M）下差异太大。

### 🟡 P2 — 健壮性 / 安全（影响稳定性和安全性）

#### P2-1. `read_file` 无路径安全检查

可以读取任意路径文件（包括系统敏感文件如 `/etc/passwd` 或 Windows 注册表）。安全策略对读操作全放行。

**建议**：
- 添加工作区边界检查（默认不允许读取工作区外的文件，除非用户确认）
- 或者添加文件大小上限（避免读 10GB 文件撑爆内存）

#### P2-2. `execute_command` 无命令白名单/黑名单

任何命令都可以执行。虽然安全策略 `analyze` 模式阻断命令，但 `auto` 模式下完全放行。

**建议**：
- 添加危险命令模式匹配（`rm -rf /`、`format` 等）
- 工具 handler 内检查命令字符串，匹配危险模式时强制要求确认（不受安全模式影响）

#### P2-3. 配置文件无 schema 校验

`agent_settings.json` 加载时对字段做基本解析，但不会校验值范围（如 `temperature: 999` 会被接受，虽然 API 会报错）。

**建议**：`CLFConfigLoader` 中加范围检查 + 非法值时使用默认值 + 日志警告。

#### P2-4. Session 文件无版本号

会话文件（`.json`）没有格式版本标记。如果未来消息格式变化，旧文件无法正确解析。

**建议**：序列化时写入 `"format_version": 1`，加载时按版本决定行为：

| 版本匹配 | 行为 |
|----------|------|
| `== 当前版本` | 正常加载 |
| `< 当前版本` | 尝试加载（旧格式兼容），`LOG_WARN("旧格式会话，部分字段可能缺失")` |
| `> 当前版本` | 拒绝加载，`LOG_ERROR("会话文件由更新版本创建，请升级 CLFCode")`，避免运行时崩溃 |
| 缺失 | 视为 v1 |

#### P2-5. `write_file` schema 缺失 `force` 参数

`CLFToolExecutor` 的安全确认逻辑引用了 `force=true` 属性（"Use Auto mode or set force=true"），但 `CLFBuiltinTools.cpp` 中 `write_file` 的 JSON Schema 没有定义这个参数。模型无法传。

**建议**：
- 在 schema 中补充 `"force": {"type": "boolean", "description": "跳过安全确认（用户已显式同意）"}`
- `force` 只作为工具参数（表示用户已确认），**不绕过全局安全模式**
- 非交互模式（block 策略）下 `force` 被忽略——全局策略优先
- 交互模式下 `force=true` 跳过工具层确认提示，但 `analyze` 模式仍需终端确认
- 语义：`force` 是"用户已同意"的信号，不是"绕过安全"的开关

#### P2-6. CLFHttpClient `m_wasAborted` 从未被设为 `true`

`ICLFHttpClient.hpp` 定义了 `m_wasAborted` 字段，`CLFAgentLoop` 检查它，但 `CLFHttpClient` 的 `abort()` 只调用 `client.stop()`，从不设置 `m_wasAborted = true`。中断检测在流式路径上依赖回调返回 false，在同步路径上完全失效。

**建议**：`abort()` 末尾设置 `m_wasAborted = true`。

#### P2-7. CLFRetryPolicy 对不可恢复的 HTTP 错误也重试

`isFatalHttpError` 只标记 400/401/402/403。404/405/409/413/422 等"请求本身有错"的状态码也会被重试 3 次，纯浪费时间。

**建议**：细化状态码重试策略：

| 状态码 | 重试次数 | 退避 | 理由 |
|--------|:---:|------|------|
| 429, 5xx, 超时 | 3 次 | 指数退避 | 临时性问题，恢复后可重试 |
| 400, 401, 403, 404, 405, 413, 422 | 0 次 | — | 请求本身错误，重试无效 |
| 其他 4xx | 1 次 | 线性 | 不确定原因，给一次机会 |

#### P2-8. `get_current_time` 仅 Windows 可用

用了 `localtime_s`（MSVC 特有），无 POSIX 分支。Linux/macOS 上永远返回 `"[Error] Failed to get local time"`。

**建议**：`#ifdef _WIN32` 用 `localtime_s`，`#else` 用 `localtime_r`。

#### P2-9. `execute_command` 非零退出码一律视为失败

`exitCode != 0` → `success: false`。但 `grep`（无匹配返回 1）、`diff`（有差异返回 1）等大量命令用非零退出码传递有用信息。模型收到 `success: false` 会误判。

**建议**：**不用 stdout 判定**（`touch newfile` 无 stdout 但成功，`ls /nonexist` 无 stdout 但失败）。改用**命令白名单**：

| 命令 | 退出码 1 | 判定 |
|------|:---:|------|
| grep, rg | 无匹配 | 成功（输出为空） |
| diff | 有差异 | 成功（输出差异内容） |
| 其它所有命令 | 非零 | 失败 |

`executeCommand` handler 中检查命令名前缀匹配白名单，命中则对退出码 1 特殊处理。

#### P2-10. CLFConfigLoader 头文件注释 JSON 结构错误

`CLFConfigLoader.hpp` 22-36 行的注释示例使用 `"api"` 键名，但实际代码读取的是 `"connection"` 和 `"chat_completions"`。照注释写配置会不生效。

**建议**：修正头文件注释。

#### P2-11. `findProjectRoot` 使用 ANSI API

Windows 路径调用 `GetModuleFileNameA`，非 ASCII 路径字符会丢失。

**建议**：改为 `GetModuleFileNameW` + `WideCharToMultiByte` 转 UTF-8。

### 🟢 P3 — 功能增强（锦上添花）

#### P3-1. 无 web_fetch / web_search 工具

没有联网搜索能力，模型只能凭训练数据回答。

**建议**：后续引入 `web_fetch` 工具（HTTP GET → Markdown），可选 `web_search`（调用搜索 API）。

#### P3-2. 不支持多会话

一次只能有一个活跃会话，不能在不同项目/上下文之间切换。

**建议**：`/session list` + `/session switch <n>`。先不急，属于高级功能。

#### P3-3. 无配置文件热重载

改 `agent_settings.json` 后必须重启 CLFCode 才生效。

**建议**：`/reload` 命令重新加载配置。

#### P3-4. `edit_file` 空 `old_string` 导致死循环

`content.find("")` 返回 0，唯一性检查遍历所有位置匹配 `content.size() + 1` 次才报错。

**建议**：`old_string.empty()` 提前返回明确错误。

#### P3-5. 无操作系统信号处理器

`SIGINT`/`SIGTERM`/`SetConsoleCtrlHandler` 均未注册。进程被 kill 时无法保存会话。

**建议**（注意实现安全）：
- 信号处理器中**只做最小工作**：设置 `volatile sig_atomic_t` 全局标志
- 主循环每次 turn 开始前检查该标志，为真则调用 `saveSession` + 退出
- **禁止在信号处理器中直接调用 `saveSession`**（涉及文件 I/O 和内存分配，不安全）
- Windows：`SetConsoleCtrlHandler`；Linux：`sigaction`

#### P3-6. Session 文件无并发锁

两个 CLFCode 实例在同一项目目录时会竞争 `latest.json`。无文件锁保护。

**建议**（采用系统级锁，避免僵尸锁）：
- 锁文件路径：`<project_root>/.clf/lock`
- Linux `flock()` / Windows `LockFileEx()`（需 `OVERLAPPED` 结构）
- 进程退出时内核自动释放，无需清理
- **锁冲突行为**：获取锁失败时打印错误并退出——`[ERROR] 会话目录已被另一个 CLFCode 进程锁定，请关闭其他实例后重试`，不 crash，不静默忽略
- 降级方案：`.lock` 文件写入 PID + 时间戳，新实例检查 PID 是否存活，僵尸锁自动回收

#### P3-7. `findProjectRoot` 无深度限制

在没有 CMakeLists.txt 的目录中会遍历到文件系统根目录，可能跨越慢速网络挂载。

**建议**：限制最大向上遍历深度（如 20 层）。

### 第一批详细步骤（建议先做）

#### Step 1：CLI 参数解析

**新增文件**：`src/CLFCore/CLFArgParser.hpp/.cpp`

命名空间中解析 `argc/argv`，返回结构化结果：

```cpp
struct CLFLaunchArgs {
    bool showHelp    = false;
    bool showVersion = false;
    bool allowWrite  = false;        // --allow-write
    std::string configPath;          // --config
    std::string projectRoot;         // --project-root
    std::string oneShotPrompt;       // --prompt（非空 = 非交互模式）
    std::string promptFilePath;      // --prompt-file（从文件读取 prompt）
};
```

**修改**：`main.cpp` 先解析参数，再根据结果走不同分支。

**实现细节**：
- `--prompt` 和 `--prompt-file` **互斥**：同时非空时报错 `[ERROR] Cannot use --prompt and --prompt-file together` 并 `exit(1)`，不静默覆盖
- 非交互模式下 CLFLogger 强制输出到 stderr，仅最终结果写入 stdout（保证 `> result.txt` 拿到干净输出）

#### Step 2：非交互模式

`--prompt` 或 `--prompt-file` 触发时：
1. 初始化同交互模式（加载配置、日志、Builder，但跳过 FTXUI 组件树初始化）
2. prompt 来源：`--prompt` 直接用参数值，`--prompt-file` 读取文件内容（支持多行）
3. 安全策略：默认 `block`（仅 Read），加 `--allow-write` 则 `auto`
4. 调用 `agent.runTurn(prompt)`
5. 输出结果到 stdout + 退出

#### Step 3：search_content 工具

**新增文件**：`src/CLFTools/CLFSearchContent.cpp`

```cpp
// handler 实现:
// 1. 递归遍历 directory（depth-first，设置最大深度 20）
// 2. 如果有 fileTypes 参数，按扩展名过滤文件
// 3. 对每个文件逐行用 std::string::find 匹配 pattern（纯文本）
// 4. 跳过目录: .git node_modules __pycache__ build dist .cache vendor
// 5. 单文件 > 1MB 跳过并备注
// 6. 限制最大结果行数 500，超出截断标记
// 7. 返回格式: file:line: content
```

**注册**：加入 `CLFBuiltinTools::registerBuiltinTools()`，风险等级 Read。

**fileTypes 处理细节**：
- 格式：逗号分隔带点号扩展名，如 `".cpp,.h,.txt"`，按 `,` 分割并 trim 空格
- 统一转小写比较（`path.extension()` 转小写后匹配；注意 Windows 上 `extension()` 返回小写，Linux 保留原始大小写，需主动转小写）
- 无效项（缺失点号、空字符串）：`LOG_WARN` 并跳过该项，不阻断整体搜索

## 七、验证标准

1. `CLFCode --version` 输出版本号
2. `CLFCode --help` 输出参数列表（含 `--prompt-file` / `--allow-write`）
3. `CLFCode --prompt "hello"` 非交互模式（block 策略），执行后退出
4. `CLFCode --prompt "write to src/main.cpp" --allow-write` 非交互 + 允许写
5. `CLFCode --prompt-file ./task.md` 从文件读取 prompt
6. `search_content("main", ".")` 返回匹配结果，跳过 node_modules
7. `/model deepseek-v4-flash` 运行时切换模型
8. 配置 `temperature: 999` → 日志警告 + 回退默认值
9. `execute_command("rm -rf /")` 在任何安全模式下都触发确认
10. `edit_file("", "x", old_string="")` 空 old_string 立即返回错误
11. `search_content` 跳过 `.git/`、`node_modules/`，不扫描 >1MB 文件，结果 ≤500 行
12. 非交互模式 `--prompt "rm -rf /"` 被 block 拒绝；加 `--allow-write` 后方可执行
13. 同时启动两个 CLFCode 实例，第二个提示"会话被锁定"后退出（不 crash）
