## 二、jsonl 新数据模型与落库订阅者

### 2.1 现状问题（取证）

- 装饰行（✻/📋）混在 assistant content 落库——数据不纯
- 消息无稳定 id（turnId/callId）——跨面对齐无键
- tool 消息落库但**回显跳过**；summary 行落库但**回显跳过**——用户痛点"还原旧会话显示不全"

### 2.2 新落库模型（jsonl 行结构演进，追加式兼容）

```
header      （不变）
turn        → messages 保持（assistant content 已无装饰——1.1 生效）+ 新增字段：
              turnId（回合稳定 id）+ 每消息 msgSeq（总线 seq）
todo_snapshot（不变）
complete    （不变）
summary     （不变）
```

**新行类型**（用户拍板采纳 2026-10-12）：`event_log`——工具调用/结果事件明细（callId/name/ok/summary/seq，一行一工具，回合末随 turn 落盘），供恢复时完整重建"当时执行了什么"（用户痛点根治：resume 能看到工具痕迹）。老文件无此行 = 兼容跳过（既有"未知类型静默跳过"安全网）+ 老文件从 turn 行内 tool 消息提取摘要兜底。

### 2.3 落库订阅者（CLFSessionWriter，生产者-消费者定案 2026-10-12 用户定调）

- 新增 `CLFSessionWriter`（CLFCore）：总线订阅者（Lossless），消费 TurnFinished/TodoUpdated/ToolStarted/ToolFinished 等语义帧
- **内部生产者-消费者（两层队列各司其职）**：

```
AgentLoop 发事件 ──▶ 总线(writer 订阅队列，有界) ──▶ 订阅回调【只入队，立即返回】
                                                       │
                                                       ▼
                   writer 内部队列（大容量/水位 flush）──▶ 独立落盘线程（攒批写盘）
```

- **必要性**（设计评审实抓）：若订阅线程直接写盘，磁盘慢 → writer 订阅队列积压 → Lossless 满 → 反压阻塞 AgentLoop 发事件——异步落盘目标被破坏。订阅回调只做入队（快操作永不阻塞），落盘线程独立消费
- **纪律（用户定调 2026-10-12："产生就存盘"）**：① **事件到达即写**（落盘线程逐条写，不攒批——事件频率每回合 <100 条，攒批属过度设计）② 回合边界语义自动满足（TurnFinished 事件一到即写，崩溃丢失窗口 ≤ 一个回合）③ 析构 drain（退出前冲干净队列）④ 落库失败仅 warn（现语义）⑤ "基本不积压"目标：写盘速度远高于事件产生速度，队列常态接近空
- 现有同步追加写路径（finishTurn → addMessage → appendTurnLine 差集）**切换**为 writer 驱动；CLFSessionFileCtx 保留（会话文件状态管理），写入调用改由 writer 持有

### 2.4 老会话兼容（硬约束）

- 老 jsonl（含装饰行）解析时：**剥离程序已知精确格式**（用户拍板：只剥已知、不误伤）——worked 行（`\n \n✻ ` 前缀 + ` for Ns\n \n` 结尾）与 📋 收尾段（`\n📋 任务清单` 起、已知拼法）行级精确匹配剥离；模型内容里合法的 ✻/📋 不动；只影响回显解析，**不改写原文件**；TodoRound/complete 行照旧独立显示
- 老文件无 event_log：跳过（无工具痕迹，回显保持"内容完整"水平）
- 老文件无 turnId：回显时生成临时 id（仅显示用）

## 三、resume 回显重做（用户痛点：显示不全）

### 3.1 现状取证

`collectEchoLines`（CLFSessionFileCtx.cpp）：turn 行 → User/Assistant 行 + TodoRound；**tool 消息跳过**、summary 行不回显、todo_snapshot 行不回显。

### 3.2 重做方案（事件重放定案，2026-10-12 用户推演确认）

**核心转变**：resume 回显从"UI 读文件独立解析（collectEchoLines）"改为"**后端重放事件流、UI 走与正常对话同一渲染路径**"——消灭两套显示逻辑，前后端分离的理想形态（用户定调："理论上应该是与正式请求后端接收信息是一个流程"）。

**流程**：`/resume` 列表选择 → TUI 发 `ResumeRequested{sessionFile}` → 后端读 jsonl 逐行重放 History* 事件（文件行序 = seq 序）→ 适配器按 History* 渲染（历史样式/折叠）→ 后端同一处理内 loadJsonl 重建 context（数据层，不走事件）→ 重放毕回 idle。

**协议补充**（分册 1 协议头基础上新增 History* 事件组）：

| 事件 | 载荷 | 适配器渲染 |
|---|---|---|
| `HistoryHeader` | model / startedAt / skills | 会话头弱化行 |
| `HistoryUser` | text | "● 用户" 弱化行 |
| `HistoryAssistant` | text | 正常内容渲染（折叠块内） |
| `HistoryToolTrace` | callId/name/ok/summary | `↳ 工具名 摘要` 弱化行（新文件 event_log 行 / 老文件 turn 行提取——差异收敛在重放器） |
| `HistorySummary` | text | 📦 摘要折叠行 |
| （清单） | 复用 `TodoUpdated` | TodoRound 快照显示（既有机制） |
| `ResumeDone` | — | 结束回显 |

**副作用防护（天然成立）**：History* 不在 runTurn 消费路径；CLFSessionWriter 只订阅 live 语义帧（不回写）；重放不可能触发 API/工具。

**折叠交互**：适配器把 History* 渲染进折叠块（复用 showFoldedBlock，Ctrl+R 展开语义不变——现状观感保持）。

**collectEchoLines 删除**：UI 侧独立回显解析代码整体移除——TUI 只剩"事件→渲染"一套逻辑。

| 数据 | 现状 | 重做后 |
|---|---|---|
| user/assistant 消息 | 回显（含装饰） | 重放回显（装饰剥离——重放器解析时剥） |
| tool 消息 | 跳过 | **回显**（HistoryToolTrace） |
| summary 行 | 跳过 | **回显**（HistorySummary 折叠） |
| TodoRound/complete | 回显 | 保持（TodoUpdated 重放） |
| ✻/📋 装饰 | 原样回显（在 content 内） | 剥离；清单经 TodoRound 独立显示 |

### 3.3 显示重建原则

- 数据纯净后，**视觉由 UI 重建**：回显时 worked 行/清单行不再重建（对话流语义 = 内容 + 清单快照，装饰是历史呈现细节）——与用户"UI 只负责渲染"定调一致
- 观感变化点（评审确认）：resume 回显比现状**信息更多**（工具痕迹/摘要），装饰行消失——预期变化而非回归

## 四、TipsBar 与状态行计时数据源迁移

### 4.1 现状

- TipsBar：`activityCount()`（ICLFOutput）判定静默；render(busy) 快照 + tick 回合外清零（2026-10-12 刚修）
- 状态行计时：AgentLoop turnTimer 50ms 拼 "Working for Xs…"（1.1 已迁移）

### 4.2 迁移方案

- TipsBar 构造注入 bus（可选，nullptr = 兼容旧路径）：订阅 ContentDelta/ToolFinished（Coalescing）→ 内部活动计数（替代 activityCount）
- busy 感知保留（render 快照机制不动）——只是"活动"数据源从 activityCount 换为事件计数
- ICLFOutput::notifyActivity/activityCount **保留**（接口零改动承诺；分册 3 并发后 ToolExecutor 事件也会驱动）
- 状态行计时器：适配器侧新增 50ms timer（TurnStarted 启动 / TurnFinished+Interrupted 停止）——**UI 自计时**（用户定调 7）
- **TurnTimerGuard 去留（审查补充 2026-10-12）**：分册 1 步骤 0 的 TurnTimerGuard 在文案迁移后**保留转圈动画驱动**（requestRefresh）**、删除状态行文案生成**——guard 不整体移除，职责一分为二（动画归 guard、计时归适配器）

## 五、confirm 切换总线路径

### 5.1 现状链

`ToolExecutor` → `AgentLoop::m_confirmCallback` → `CLFRepl:117 setConfirmCallback` 绑定 `Terminal::confirm`（阻塞，UI 线程执行确认条）。

### 5.2 切换方案

- AgentLoop 持 bus 后：m_confirmCallback 实现改为 `bus->publishRequestAndWait(ConfirmRequested{requestId,prompt}, timeout)`
- 适配器订阅 ConfirmRequested → UI 线程调 `Terminal::confirm` → publish ConfirmResponse{requestId,accepted}
- 超时默认拒绝（**60s**，用户拍板参照 Claude Code——与现状无限等待为预期行为变化）
- CLFRepl:117 的 setConfirmCallback 绑定**删除**（AgentLoop 自持 bus 即不再需要注入）——CLFRepl 装配瘦身一步

## 八、风险与开放项

- **装饰剥离误伤**：模型内容含合法 ✻/📋 文本 → 剥离模式匹配需严格（行级 + 精确前缀）；老文件剥离仅影响回显不改原文件
- **labels 迁移面**：AgentLoop 构造参数变化波及 qa（qa_CLFAgentLoop 大量用例构造 AgentLoop）——设计评审估影响面，必要时保持构造兼容（默认参数）
- **确认超时时长定值**（与分册 1 §六 同项，合并定）
- **落库异步化时序**：回合结束到落库完成有窗口——程序崩溃丢最后事件的残余风险（现同步写同样有——追加写本身即尽力而为；writer 增加"回合边界 flush"纪律）
