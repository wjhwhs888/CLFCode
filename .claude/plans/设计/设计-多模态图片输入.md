# 设计-多模态图片输入（第一批：工具读图 + 软着陆）

- **状态**：设计稿 v2（2026-10-30 修订，待用户确认后实施）
- **调研依据**：`分析/分析-多模态图片输入机制调研.md`（dsh 源码 + Claude Code 文档 + DeepSeek 协议证据）
- **上游能力**：`deepseek-flash`（V4.1-Flash）原生支持图片输入；OpenAI 兼容 `image_url`
- **第一批范围**：模型自己定位目录/文件名，调用 `read_file` 读取图片；宿主把图片注入上下文。**不在本批**：剪贴板粘贴、宿主自动解析输入路径、公网 URL、终端图片像素渲染

---

## ⚠ 口径变更（2026-10-30，取代 v1）

| 议题 | v1（初稿） | v2（现行） | 依据 |
|---|---|---|---|
| 图片入口 | 宿主解析输入中的本地路径并自动附加 | **工具读图**：模型用 list_directory/搜索定位，`read_file` 读取 | 用户实际用法（自然语言指路 + 模型自己找）；dsh/Claude Code 同路线 |
| 模型不支持视觉 | 发请求前**拦截报错** | **软着陆跳过**：不注入图片、不报错、对话继续 | 用户定调「可以用不上，不能没有，不能因为有就报错」 |
| 超限行为 | 拦截报错 | 工具/序列化层软降级（跳过该图或最旧图降文字占位） | 同上 |
| 能力判定 | 配置项显式开关 | 配置表 + `flash` 兜底 + `/vision` 会话开关（控制是否尝试发送） | 用户定调「动态自适应，不要锁死」 |

> 用户原话（2026-10-30）：「这个就是属于正常设计了，咱们 agent 支持多模态，大模型不支持那就没办法了，可以用不上，不能没有，也不能因为有就报错，得软着陆，跳过。」

## 一、目标与边界

### 1.1 目标（验收标准）

1. 用户自然语言指路（"测试目录下放了图片，叫 dsh 桌面端"）→ 模型用现有目录/搜索工具定位 → 调用 `read_file` 读取图片 → 模型能看到图片内容并回答。
2. 多模态能力完整具备：PNG / JPEG / GIF / WebP 魔数识别、读取、编码、注入、落库、恢复。
3. 当前模型不支持视觉、开关关闭、文件过大/丢失时：**跳过图片，对话继续**，不报错、不中断回合；模型收到文字说明后可自行重试或总结。
4. `/vision` / `/vision on` / `/vision off` 运行时开关：不改配置、不重启即可开启/关闭图片尝试。
5. 会话落库存路径引用；resume 后图片消息可恢复（重读文件，丢失降级文字）。
6. 历史图片最近 3 轮保留，更早降级文字占位；text-only 模型下所有历史图片降级。
7. 纯文本链路行为逐字不变。

### 1.2 边界（不归本批管）

- 剪贴板图片粘贴（CF_DIB + WIC）
- 宿主自动解析用户输入中的图片路径（v1 方案，暂不实施）
- 公网图片 URL
- 终端内图片像素渲染（只显示路径/大小占位）
- 图片压缩/缩放/OCR（交给 API；超大图由发送层降级）
- 图片生成、多模态输出
- 非 OpenAI 兼容协议

### 1.3 用户拍板【已定】

| 议题 | 结论 |
|---|---|
| 第一批入口 | 工具读图为主 |
| 持久化 | jsonl 只存路径引用 |
| 历史图片 | 最近 3 轮保留，更早文字占位 |
| 路径边界 | 模型调用 `read_file` 时沿用现有工作区校验（`allow_absolute_read` 逃生口） |
| 模型能力 | 配置表 + `flash` 兜底；不支持时软着陆跳过 |
| 运行时开关 | `/vision on/off` + `agent.image_input`（默认 false） |
| 限制值 | 单图 10 MiB、4 张/请求、总量 20 MiB（超限软降级，不报错） |

### 3.1 `CLFImageRef`（`src/CLFTypes/CLFTypes.hpp`，`namespace CLF::CLFCore`）

```cpp
// 图片附件元信息（路径引用策略：不持有 base64，发送时按需读取编码）
struct CLFImageRef {
    std::string    m_path;       // UTF-8 路径（工具返回的原始路径）
    std::string    m_mimeType;   // "image/png" / "image/jpeg" / "image/gif" / "image/webp"
    std::uintmax_t m_sizeBytes = 0;
    std::string    m_source;     // 来源标注："tool:read_file"（落库/调试用，可空）
};
```

### 3.2 `CLFMessage` 扩展

```cpp
struct CLFMessage {
    // ...既有字段...
    std::vector<CLFImageRef> m_images;   // user：直接附带；tool：工具结果附图

```

- `role == "user"`：图片随该 user 消息发送（第一批由工具注入产生，暂不来自用户粘贴）。
- `role == "tool"`：工具读取的图片；序列化时拆为「tool 文本 + 追加 user 图片消息」。

## 四、详细设计

### 4.1 新模块 `CLFImageInput`（`src/CLFTypes/CLFImageInput.hpp/.cpp`）

放 `CLFTypes` 层：仅依赖标准库与文件系统，无 UI/网络依赖。

```cpp
class CLFImageInput {
public:
    // 按魔数识别图片格式；非图片返回 false
    // example:
    //   CLFImageRef ref;
    //   if (CLFImageInput::probe(path, ref, err)) { ... }
    static bool probe(const std::string& pathUtf8, CLFImageRef& out, std::string& error);

    // 读取文件 → "data:<mime>;base64,..."
    static bool loadAsDataUrl(const CLFImageRef& ref,
                              std::string& outDataUrl, std::string& error);

    // 发送副本的历史裁剪（不改 context）：
    //   ① textOnly=true → 所有图片清空并追加占位文本
    //   ② 否则只保留最近 rounds 个「回合」内的图片，更早清空并追加占位
    static void applyHistoryPolicy(std::vector<CLFMessage>& messages,
                                   int rounds, bool textOnly);

    // 请求级预算：数量/总量超限时从最旧图片开始降级（清空 + 占位）
    static void applyRequestBudget(std::vector<CLFMessage>& messages);

    // base64 编码（公开仅供 qa）
    static std::string encodeBase64(const std::string& bytes);
};
```

#### 魔数识别

| 格式 | 特征 |
|---|---|
| PNG | `89 50 4E 47 0D 0A 1A 0A` |
| JPEG | `FF D8 FF` |
| GIF | `GIF87a` / `GIF89a` |
| WebP | `RIFF`（0-3）+ `WEBP`（8-11） |

扩展名不参与判定（与 API 内容检测一致）。

#### 历史裁剪语义

- 回合边界 = `role == "user"` 消息（每次用户提问一条）。
- 从后往前定位第 `rounds` 个 user 消息；该消息之前的全部 `m_images` 清空，并在 `m_content` 追加 `\n[图片已省略: <path>]`。
- `textOnly == true`：全部清空，追加 `[图片已省略: 当前模型不支持图片输入]`。
- 只修改发送副本，`CLFContext` 原始消息保留引用（切回 vision 模型时按轮次规则重新判断）。

### 4.2 `read_file` 工具扩展（FileOps 插件）

`src/CLFCapabilities/FileOps/CLFFileOpsHandlers.cpp`

```cpp
std::string readFileToolHandler(...) {
    // ① 工作区校验（不变）
    // ② 大小上限 50MB（不变）
    // ③ 新增：魔数探测
    CLFImageRef ref;
    std::string probeErr;
    if (CLFImageInput::probe(path, ref, probeErr)) {
        if (ref.m_sizeBytes > kMaxImageBytes) {
            // 软失败：不附加图片，返回可读说明
            result["success"] = true;
            result["content"] = "[图片过大，未加载: " + path + "]";
            return;
        }
        result["success"] = true;
        result["content"] = "[图片: " + path + " (" + mime + ", " + sizeText + ")]";
        result["images"] = json::array({{
            {"path", ref.m_path}, {"mime", ref.m_mimeType}, {"size", ref.m_sizeBytes}
        }});
        return;
    }
    // ④ 非图片 → 原文本读取路径（逐字不变）
}
```

- 工具描述更新：说明支持读取 PNG/JPEG/GIF/WebP 图片，图片会作为视觉内容提供给模型。
- 工具 schema 不变（仍是 `path` / `offset` / `limit`）。
- 插件只返回**路径引用**，不在 DLL 内编码 base64；宿主负责读取与编码（能力门禁与协议逻辑集中在 core）。

### 4.3 宿主工具执行注入（`CLFToolExecutor` / `AgentLoop`）

执行工具拿到结果后：

```cpp
// 解析 result JSON 的 images 字段 → CLFToolResult.m_images
// 能力门禁（软着陆）：
if (!images.empty()) {
    if (!agent.isImageInputEnabled()) {
        images.clear();
        appendNotice(resultText, "[图片已跳过: 图片输入未开启（/vision on 可开启）]");
    } else if (!agent.isVisionCapableModel()) {
        images.clear();
        appendNotice(resultText, "[图片已跳过: 当前模型不支持图片输入]");
    }
}
```

- 判定顺序：会话开关 → 模型能力（开关默认 false，避免开箱即发图）。
- 跳过时工具结果仍是 `success=true`，模型看到说明后自行决定重试/总结。
- `CLFContext::addToolResult` 增加可选 `images` 参数（默认空，零破坏）。
- `CLFToolResult` 增加 `std::vector<CLFImageRef> m_images`。

### 4.4 协议序列化（`CLFProtocolAdapter`）

#### 4.4.1 user 消息带图

```json
{"role":"user","content":[
  {"type":"text","text":"用户原文"},
  {"type":"image_url","image_url":{"url":"data:image/png;base64,..."}}
]}
```

#### 4.4.2 tool 消息带图（保守方案）

`buildChatRequest` 的消息循环改为支持「一条源消息展开为多条」：

```cpp
for (const auto& msg : messages) {
    if (msg.m_role == "tool" && !msg.m_images.empty()) {
        msgs.push_back(serializeToolText(msg));       // tool 消息保持纯文本
        msgs.push_back(serializeToolImagesAsUser(msg)); // 紧随其后的 user 图片消息
        continue;
    }
    msgs.push_back(serializeMessage(msg));
}
```

追加的 user 消息形态：

```json
{"role":"user","content":[
  {"type":"text","text":"Attached image(s) from tool result: <path>"},
  {"type":"image_url","image_url":{"url":"data:image/png;base64,..."}}
]}
```

- 图片读取失败（文件被删/编码失败）→ 只发文字块 `[图片不可用: path (原因)]`，不破坏请求。
- `dump(..., error_handler_t::replace)` 兜底不变。

#### 4.4.3 发送层兜底降级

若请求返回错误且错误文本含图片相关关键词（`image` / `unsupported` / `invalid`）：

- 剥离本次请求中的所有图片块，替换为文字占位，重试一次；
- 仍失败 → 按普通错误处理（现有重试逻辑）。

> 该兜底只在 API 不接受图片时触发，正常路径零额外请求。

### 4.5 token 与窗口

`CLFTextUtil::estimateTokensForMessage`：

```cpp
total += static_cast<int>(msg.m_images.size()) * kImageTokenEstimate;  // 1024/图
```

- tool 消息附图同样计入；窗口截断自然生效。
- 自动摘要只取文本，图片不参与（函数注释写明）。

### 4.6 落库与恢复

#### 落库

- `messagesToJson`：`m_images` 非空时写
  ```json
  "images": [{"path":"E:/.../a.png","mime":"image/png","size":12345,"source":"tool:read_file"}]
  ```
- `messagesFromJson`：读取（缺省空，老文件兼容）。
- `SessionWriter`：tool 消息携带 `ToolFinished.m_images` 写入；正常轮 + 中断轮共用。
- 不存 base64（用户拍板）。

#### 恢复

- `CLFSessionReplayer`：`HistoryToolTrace` 携带 `m_images`；适配器渲染占位行。
- 恢复后发送时按当前模型能力与轮次规则重新判定。
- 文件丢失 → `loadAsDataUrl` 失败 → 文字降级。

### 4.7 TUI 渲染

- 适配器在 `ToolFinished.m_images` 非空时渲染：
  ```
   ⎿ 图片: C:\...\dsh桌面端.png (312 KB)
  ```
- resume 历史同样渲染。
- 跳过/过大/不可用：由工具结果文本承载，随现有工具结果展示。

### 4.8 能力判定与 `/vision`

```cpp
bool CLFAgentLoop::isVisionCapableModel() const;
// ① m_config.m_visionModels 精确匹配（大小写不敏感）→ true
// ② 模型名包含 "flash"（大小写不敏感）→ true（用户拍板兜底）
// ③ 否则 false

bool CLFAgentLoop::isImageInputEnabled() const;   // 会话开关，初始 = config.m_imageInput
void CLFAgentLoop::setImageInputEnabled(bool on);
```

`/vision` 命令：

| 输入 | 行为 |
|---|---|
| `/vision` | 显示模型、模型能力、会话开关、配置默认、用法 |
| `/vision on` | 开启；若模型不支持，仍开启但提示「当前模型不支持，图片会被跳过」 |
| `/vision off` | 关闭 |

命令注册进 `registerBuiltinCommands`，`/help` 与候选面板自动同步（唯一维护源）。

> 软着陆语义：开关只决定「是否尝试发送图片」，不再作为报错条件。

## 五、软着陆矩阵

| 场景 | 行为 | 模型看到 | 是否中断 |
|---|---|---|---|
| 图片正常 | 注入图片块 | 图片 + 工具文本 | 否 |
| `/vision` 关闭 | 跳过图片 | `[图片已跳过: 图片输入未开启…]` | 否 |
| 模型不支持视觉 | 跳过图片 | `[图片已跳过: 当前模型不支持图片输入]` | 否 |
| 单图 > 10 MiB | 跳过该图 | `[图片过大，未加载: path]` | 否 |
| 数量 > 4 / 总量 > 20 MiB | 最旧图片降级 | `[图片已省略: path]` | 否 |
| 魔数不支持 | 按文本读取（乱码风险）或返回提示 | 工具文本 | 否 |
| 文件读取失败 | 文字降级 | `[图片不可用: path (原因)]` | 否 |
| API 拒绝图片 | 剥离图片重试一次 | 文字占位 | 否（仅多一次请求） |
| text-only 模型 + 历史图片 | 全部降级 | `[图片已省略: 当前模型不支持图片输入]` | 否 |
| 路径不存在 | 现有工具错误路径 | 工具错误 JSON | 否（模型自行处理） |

### 6.2 实机验证

1. 准备 `测试/image/` 放一张 PNG（用户提供）。
2. `/vision on` → 对话「测试目录下放了图片，叫 dsh 桌面端」→ 模型找目录、read_file 读图、正确描述。
3. `/vision off` → 同样提问 → 模型收到跳过说明，不报错，能总结「图片被跳过」。
4. 切换 text-only 模型（如 `deepseek-v4-pro`）→ 读图 → 跳过说明，对话继续。
5. 连续两轮追问图片内容 → 最近 3 轮内可回看。
6. resume 含图会话 → 占位行显示、继续对话正常。
7. 纯文本对话回归。

## 八、风险与待决

| 项 | 说明 | 处置 |
|---|---|---|
| tool 后追加 user 消息 | 改变消息序；模型可能误认为用户新发言 | 文本固定标注 `Attached image(s) from tool result`；dsh 同做法 |
| API 对 tool 图片的容忍度 | 本方案不依赖 tool content 数组，只依赖 user 图片（官方明确支持） | 保守路线 |
| 重复 IO | 插件探测一次、宿主编码再读一次 | 图片通常较小；后续可传字节缓存 |
| 像素尺寸 | 只限字节，超大像素可能 API 400 | 发送层降级重试兜底；后续可补头部尺寸解析 |
| 路径引用 | 文件移动/删除后历史图片失效 | 用户已拍板；文字降级可追溯 |
| `flash` 兜底误判 | 其他厂商含 flash 的纯文本模型被误判 | 请求失败由发送层降级兜底；`vision_models` 可显式声明 |
| 历史 3 轮 | 与 dsh 的「每轮重发 + 卸载」不同 | 用户已拍板；更省费用，代价是更早失忆 |
| 模型把追加 user 消息当成新回合 | 可能触发多余的总结行为 | 实机观察；必要时调整文案 |
