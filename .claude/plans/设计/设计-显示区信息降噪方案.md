# 设计：显示区信息降噪方案

> 状态：设计中 | 创建：2026-08-07 | 参考：Claude Code Display Architecture

## 〇、设计目标

遵循 Claude Code "信息降噪" 原则——**默认折叠，一键展开**，让用户聚焦协作本身。

三项改造：

| 改造 | 现状 | 目标 |
|------|------|------|
| 思考过程 | 全部实时显示（`reasoning_content` 混在内容区） | 默认折叠一行缩略，`Ctrl+O` 展开 |
| 状态栏 | 仅模式名 | 模型名 + 工作目录 + 安全模式 + 思考指示器 |
| 工具输出 | 全量内容区展示 | 成功单行绿色 ✓，失败红色详情，大输出自动折叠 |

---

## 一、思考过程折叠

### 1.0 Ctrl+O 可用性确认

Ctrl+O 是 ASCII `0x0F`（纯控制字符），FTXUI 直接映射到 `Event::CtrlO`。**不同于 ESC（`\033`，终端转义序列前缀）**——不会有 `Special({27,27})` 这类坑。Ctrl+D/N/C/V 已验证全部正常，Ctrl+O 同理。

### 1.1 折叠策略

**默认折叠**：不展示推理过程，内容区只保留一行缩略。

```
💭 Thought for 12s (~3K tokens) — Ctrl+O 展开
```

**展开后**：该行原地展开为完整推理内容（`dim` 灰色样式区分正式回复），可滚动回看。

**内联定位**：思考缩略和展开内容都在内容区流中，与后续正式回复在同一个滚动缓冲区。位置固定——思考发生的位置，不是独立固定区。和 Claude Code 行为一致。

**思考结束后**：缩略行保留在内容区（标记已完成），表示"此处有推理过程"。新 turn 开始时清空。

### 1.2 数据流改造

当前 `CLFStreamAccumulator::feedDelta()` 把 `reasoning_content` 和 `content` 混在一起返回。改为**分通道**：

```cpp
class CLFStreamAccumulator {
public:
    // feedDelta 只返回 content 部分（Agent 层 tool call 解析不变）
    // reasoning 通过以下接口单独获取：
    bool hasReasoning() const;
    const std::string& getReasoning() const;

private:
    std::string m_content;
    std::string m_reasoning;  // 新增：独立累积推理内容
};
```

### 1.3 CLFAgentLoop 改动

流式回调中，推理内容不再走 `emitContent`，改为走新接口：

```cpp
// 流式回调:
auto chunk = acc.feedDelta(delta);  // 只返回 content
if (!chunk.empty()) {
    thinking.stop();
    if (m_output) m_output->emitContent(chunk);
}
// 推理内容通过 CLFTerminal 的新方法写入思考缓冲
if (m_output && acc.hasReasoning()) {
    m_output->appendThinking(acc.getReasoning());
}
```

注意：`ICLFOutput` 接口需新增 `appendThinking()` 虚方法。

### 1.4 CLFTerminal 新增

```cpp
// 思考缓冲（与 m_contentBuffer 分离）
std::string m_thinkingBuffer;     // 当前 turn 的完整推理过程
bool m_thinkingActive = false;    // 是否正在思考中

void appendThinking(const std::string& text);
void clearThinking();             // ESC 中断或新 turn 时清空
bool hasThinkingContent() const;
std::vector<std::string> getThinkingLines() const;  // 按终端宽度换行
size_t m_thinkingBytes = 0;       // 推理内容字节数（用于 Token 估算）
```

`contentSnapshot()` 新增字段 `thinkingLines`、`thinkingActive`、`thinkingBytes`。

**缩略行 Token 估算**：
- 优先用 API 返回的 `usage.reasoning_tokens`（精确值）
- 无精确值时用 `m_thinkingBytes / 4` 估算（保守值：中文 2-3 字符/token，英文 4-5）

### 1.5 UI 层：Ctrl+O + Renderer

**CLFRepl 新增**：`bool m_showThinking = false;`

**CatchEvent 新增处理器**（在步骤 3 Ctrl+N 之后、步骤 4 Ctrl+C 之前）：

```cpp
// Ctrl+O: 切换思考过程显示
if (e == ftxui::Event::CtrlO) {
    m_showThinking = !m_showThinking;
    return true;
}
```

**Renderer 思考区**（在内容区之前，仅折叠/展开时显示）：

```cpp
// 思考缩略（仅当本 turn 有推理内容时渲染；无推理时 Ctrl+O 无视觉变化）
if (snap.thinkingActive || !snap.thinkingLines.empty()) {
    if (snap.thinkingActive) {
        contentLines.push_back(dim(text("  💭 Thinking… — Ctrl+O 展开")));
    } else {
        contentLines.push_back(dim(text(
            "  💭 Thought for " + thinkingDuration + " (~" + estTokens + " tokens) — Ctrl+O 展开")));
    }
}

// 思考展开（Ctrl+O 后展示全部推理内容）
if (m_showThinking && !snap.thinkingLines.empty()) {
    for (auto& l : snap.thinkingLines)
        contentLines.push_back(dim(text("  💭 " + l)));
    contentLines.push_back(separator());
}
```

**状态栏提示增强**：模式的 `ctrl+o` 提示融入状态栏右侧。

## 二、状态栏增强

### 2.1 现状

```cpp
auto modeLine = ftxui::dim(ftxui::hbox({
    ftxui::text("  " + m_dispatcher->modeName() + " mode on"),
}));
```

仅模式名一行，信息极少。

### 2.2 目标

```
  deepseek-v4-flash │ 📁 testCLFCode │ 🔒 edit │ ctrl+o: 思考
```

左侧信息 + 右侧快捷键提示，同行。`dim` 样式（灰色），不抢主内容注意力。

### 2.3 数据来源

| 信息 | 来源 | 获取方式 |
|------|------|----------|
| 模型名 | `m_agent.getConfig().m_modelName` | 重建 CLFRepl 时已有引用 |
| 工作目录 | `CLFConfigLoader::getWorkingDir()` | `printBanner()` 已调用 |
| 安全模式 | `m_dispatcher->modeName()` | 已有 |
| 快捷键提示 | 静态字符串 | `ctrl+o: 思考` |

### 2.4 实施

`CLFRepl` 渲染器中**替换** `modeLine`。无需改任何接口。`m_agent` 是引用成员，直接可用。

## 三、工具输出精简

### 3.1 现状

`CLFToolExecutor::execute()` 中每个工具都输出完整格式：

```
● tool_name(param)
  ⎿ ✓ result_text
```

长篇输出淹没内容区。

### 3.2 目标

| 结果 | 显示 |
|------|------|
| 成功（≤200 字符） | `✓ tool_name(param)` — 绿色单行 |
| 成功（>200 字符） | `✓ tool_name(param) — N lines, M chars` — 折叠概要 |
| 失败 | `✗ tool_name(param) — reason (scroll for full detail)` — 红色（reason 截断 100 字符） |
| 确认栏拒绝 | `✗ denied` — 红色单行 |

### 3.3 实施

`CLFToolExecutor` 修改 `formatToolResult()` 返回值中增加大小信息。`execute()` 循环中根据成功/失败 + 大小决定输出格式：

```cpp
if (rd.ok && rd.text.size() <= 200) {
    if (m_output) m_output->emitContent("  ✓ " + call.m_name + "(" + keyParam + ")\n");
} else if (rd.ok) {
    if (m_output) m_output->emitContent("  ✓ " + call.m_name + "(" + keyParam
        + ") — " + std::to_string(rd.lines) + " lines, " + std::to_string(rd.chars) + " chars\n");
} else {
    if (m_output) m_output->emitContent("  ✗ " + call.m_name + "(" + keyParam
        + ") — " + rd.text + "\n");
}
```

## 四、ICLFOutput 接口新增

```cpp
// ========== 思考内容输出（与 emitContent 分离） ==========
virtual void appendThinking(const std::string& text) = 0;
virtual void clearThinking() = 0;  // ESC 中断或新 turn 时调用
```

### 4.1 ESC 中断时的思考清理

`CLFAgentLoop` 中断路径中调用 `m_output->clearThinking()`：
- ESC 中断 → `clearThinking()` → `m_thinkingBuffer` 清空 + `m_thinkingActive = false`
- 新 `runTurn()` → 开头调 `clearThinking()`（可选）或依赖缓冲自然覆盖
- `/clear` → `clearThinking()`

## 六、分步实施

```
步骤 1：接口 + SSE 分通道（数据层，可独立验证）
  ├── ICLFOutput 新增 appendThinking() / clearThinking()
  ├── CLFStreamAccumulator m_reasoning 独立累积
  └── feedDelta() 只返回 content，getReasoning() 单独取

步骤 2：CLFTerminal 思考缓冲（存储层）
  ├── m_thinkingBuffer / m_thinkingActive / appendThinking() / clearThinking()
  ├── contentSnapshot() 扩展 thinkingLines + thinkingActive + thinkingBytes
  ├── Token 估算：优先 usage.reasoning_tokens，回退 size/4
  └── 新 turn / ESC 中断 清空

步骤 3：CLFAgentLoop 接入 + ESC 中断清理
  ├── 流式回调中 reasoning → appendThinking()
  └── 中断路径中 → clearThinking()

步骤 4：CLFRepl UI（折叠/展开）
  ├── CatchEvent: Ctrl+O 切换 m_showThinking
  └── Renderer: 思考缩略（始终）+ 展开区（m_showThinking 时）

步骤 5：状态栏增强（独立任务）
  └── 替换 modeLine → 模型名/目录/模式/快捷键提示

步骤 6：工具输出精简（独立任务，含 reason 截断 100 字符）
  └── CLFToolExecutor: 成功折叠(200 字符阈值) + 失败 reason 截断

步骤 7：端到端验证
```

**步骤 1-3 完成时**：推理内容已分通道存储，UI 未变——可通过日志验证数据正确性。
**步骤 4**：纯 UI 改造，风险最低。
**步骤 5/6**：互不依赖的独立任务。

## 七、风险

| 风险 | 缓解 |
|------|------|
| ICLFOutput 接口新增方法 → Mock 测试需同步 | `MockOutput` 已删除，`qa_CLFAgentLoop` Mock 仅需空实现 |
| `Ctrl+O` 终端兼容性 | ASCII 0x0F，所有终端支持，已验证 Ctrl 系列全正常 |
| 思考内容内存增长 | 每次 `runTurn()` 新 turn 清空 `m_thinkingBuffer` |
| 工具输出折叠丢失信息 | 完整内容仍在内容区保留，折叠仅影响即时展示格式 |
| 思考内联 vs 固定区 | 内联选择：缩略行在流中，展开原地插入，与 Claude Code 一致 |

## 八、与现有功能的关系

| 现有功能 | 影响 |
|------|------|
| ESC 中断 | 无影响——中断时清空 `m_thinkingBuffer` |
| `/clear` | 清空内容区时同步清空 `m_thinkingBuffer` |
| 历史导航 ↑/↓ | 无影响——仅作用于 input 组件 |
| 确认栏 | 无影响 |
| 滚动 | 展开的思考内容在 `allLines` 中，滚轮正常覆盖 |
