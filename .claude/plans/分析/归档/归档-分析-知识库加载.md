# 问题-知识库加载

## 背景
`data/skills/` 下有 5 个 md 文件，定义了 Agent 的行为规则（L1 编码宪法、L2 架构原则、L3 调试/审查/测试规则）。
需要设计何时加载、如何注入到 system prompt。

## 当前状态
- `data/skills/constitution.md` — L1 始终加载规则
- `data/skills/architecture.md` — L2 架构设计原则库
- `data/skills/debug.md` — L3 Debug 标准工作流
- `data/skills/code_review.md` — L3 代码审查清单
- `data/skills/unittest.md` — L3 单元测试生成规则
- `data/README.md` — 定义了按需加载策略（但未实现）
- `CLFAgentLoop` 中无加载逻辑

## 待解决

### 加载策略设计
| 级别 | 触发条件 | 加载方式 |
|------|----------|----------|
| L1 编码宪法 | 每次会话 / 每个请求 | system prompt 常驻 |
| L2 架构原则 | 涉及架构设计 / 新建模块 | 追加到 system prompt |
| L3 Debug | 用户报告错误 / 编译失败 | 追加到 system prompt |
| L3 Code Review | 用户要求审查代码 | 追加到 system prompt |
| L3 Unit Test | 用户要求写测试 | 追加到 system prompt |

### 实现细节
1. L1 内容如何注入？初始 system prompt？每个请求都带？
2. L2/L3 按需加载的触发机制：用户意图识别？命令触发？
3. Token 预算：规则内容占用上下文，需权衡详细程度
4. 知识库文件变更时是否需要热重载
