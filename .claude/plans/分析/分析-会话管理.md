# 问题-会话管理设计

## 最终方案

用户习惯：次日开工只带 CLI.md + progress.md + plans，极少量回看旧会话。
设计目标：**极简，够用，不做过度设计**。

## 功能边界

| 功能 | 方案 | 优先级 |
|:---|:---|:---:|
| 崩溃恢复 | 当前会话自动存盘，启动时检测未完成会话 → 提示恢复或丢弃 | 🔴 必须 |
| 会话列表 | `/history` 列出最近 10 条（日期 + 首条用户输入作为标题） | 🟡 有用 |
| 历史回看 | 不需要搜索/索引/跨会话引用 | ❌ 不做 |
| 自动清理 | 超过 30 天的会话文件自动删除 | 🟢 锦上添花 |

## 文件结构

```
doc/contextHistory/
├── 2026-07-24.json              ← 正常退出保存
├── 2026-07-24_incomplete.json   ← 崩溃/未正常退出
└── 2026-07-23.json
```

## 启动流程

1. 检查 `*_incomplete.json` → 有就问"上次会话未完成，是否恢复？"
2. 没有则新开会话
3. `/exit` 正常退出 → 保存并去掉 `_incomplete` 后缀
4. 每轮对话自动保存当前状态（防止崩溃丢失）

## 存储格式

JSON，字段：日期时间 · 模式 · 消息数组 · 元数据

## 涉及文件
- `src/CLFCore/CLFContext.cpp`（序列化/反序列化）
- `src/CLFCore/CLFAgentLoop.cpp`（启动恢复逻辑）
- `src/main.cpp`（`/history` 命令）
