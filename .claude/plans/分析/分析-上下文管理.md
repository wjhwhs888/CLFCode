# 问题-上下文管理

## 背景
Token 估算和上下文截断直接影响 Agent 智商。
长文件读入、多轮对话、工具结果大量文本时，不合理截断会导致 Agent "忘事"。

## 当前状态
- `CLFContext::estimateTokens()` — 简单按 `字符数 / 4` 估算（中英文精度很差）
- `CLFContext::getMessages()` — 从旧到新截断，保留最新消息
- 无 system prompt 预留机制（system 消息可能被截掉）

## 待解决

### Token 估算精度
- 英文：1 token ≈ 4 字符（还行）
- 中文：1 汉字 ≈ 2-3 token（`/4` 严重低估）
- 混合文本：无法简单用字符数估算
- **方案**：考虑引入 tokenizer（如 tiktoken C++ 移植）

### 截断策略优化
1. system prompt 永不截断（最高优先级保留）
2. 优先丢弃中间轮次的工具调用/结果（保留首尾）
3. 单条消息过长时的内部截断 + 标记 `[truncated]`
4. 上下文窗口动态分配：system 占 X%，对话历史占 Y%，工具结果占 Z%

### 长内容处理
- `readFile` 返回 10 万行代码怎么办？
- 工具结果自动摘要？还是限制最大返回长度？
- 文件内容分页？（"文件太长，已截取前 500 行"）

### 上下文压缩
- 多轮对话后，是否需要自动摘要旧对话
- 类似 Claude 的 "conversation summary" 机制
